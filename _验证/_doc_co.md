## 附录 CO　金额计算专项核查（2026-10-31）

### 一、计费顺序（批量出账）

```
1. 校验收费项目/计费方式/费用区间
2. 扫描生效合同（EFFECTIVE/RENEWING，租期与费用区间有交集）
3. 幂等检查（同合同+同项目+同账期/重叠区间跳过）
4. 计算计费月数（按合同租期 ∩ 费用区间，逐月按天折算）
5. 计算数量（按套/面积/床位/人数/间夜）
6. 租金类：取合同月租 × 月数；其他：计费项目单价 × 数量 × 月数
7. 套用规则（EXEMPT 归零 / DISCOUNT 打折；TIERED 按阶梯）
8. 金额四舍五入 2 位
9. 写账单：应收、减免、滞纳金、已收、已免、待缴、状态
```

### 二、字段对应

| 计算项 | 取数来源 | 写入字段 |
|---|---|---|
| 应收 | 合同月租×月数（RENT）或计费项目×数量 | `bill_amount` |
| 减免 | 规则/补贴冲减 | `discount_amount`、`waived_amount` |
| 滞纳金 | 手工/接口传入 | `late_fee` |
| 已收 | 收款核销 | `paid_amount` |
| 待缴 | 应收 − 减免 + 滞纳金 − 已收 − 已免 | `payable_amount` |
| 账单状态 | 待缴 ≤0 → 已缴；部分核销 → 部分缴纳 | `bill_status` |

### 三、本次核查发现并修复

| 问题 | 原计算 | 修复后 |
|---|---|---|
| 退租结算押金 | 取合同 `deposit_amount`（应缴额） | 取押金台账 `balance_amount`（实际可退余额），无台账才回退合同 |
| 退租结算欠费 | 按 `house_id` 汇总，且漏减免/滞纳金，字段名 `status` 导致查询异常被吞 | 按 `contract_id`，`bill_amount - discount_amount + late_fee - paid_amount - waived_amount` |
| 押金退款驳回 | 创建时已扣押金，驳回不回补 | 驳回原子回补 `refund_amount/balance_amount` 并重算状态 |
| 押金退款状态 | 创建后余额变了状态不刷新 | 创建/驳回后重算押金状态 |
| 补贴标准生效期 | 按 `today` 匹配 | 按补贴周期所在月匹配生效起止 |
| 合同租金规则 | 合同租金覆盖后完全绕过规则 | 仍支持 EXEMPT 归零、DISCOUNT 打折 |
| 折扣率 | 未校验，可 >1 或为负 | 限制 0~1 |
| 退租退款上限 | 可手工填超过押金余额 | 不得超过台账可退余额，且不得为负 |
| 抄表上次读数 | 只取“日期更早”，同日多次读数会重复计费 | 取同日期最近一条（日期、ID 倒序） |

### 四、验证

| 场景 | 结果 |
|---|---|
| 合同月租 900 出账 | 应收 900、减免 0、待缴 900 |
| 补贴 200 抵扣租金 | 账单减免 200、待缴 700、状态部分缴纳 |
| 退租结算（押金台账 1800） | 预览押金 1800、欠费 0、应退 1800 |
| 押金退款 300 → 驳回 | 余额 700 → 1000，状态 PARTIAL_REFUND → HELD |
| 一键验收管线 | 16 项全部通过 |

### 五、仍存在的计算风险（未改，需业务确认）

1. **批量出账页面没有规则选择器**：规则只能通过接口 `ruleId` 传入，页面批量出账实际不会用 DISCOUNT/TIERED/EXEMPT 规则；
2. **按人/按床位计费的数量取房源 `maxCapacity`**，不是合同实际保障人口或床位数，人数变化后金额不变；
3. **阶梯计价不乘计费月数**，面积/租金类阶梯在不足月时不折算；阶梯上下限未校验排序；
4. **抄表计费不套规则**（阶梯电价、折扣不生效），只按单价×用量；
5. **滞纳金没有自动计算**，只有手工/接口传入；
6. **资金流水 `balance_after` 无并发锁**，并发记账可能得到相同余额；
7. **换房完成后押金台账没有迁移到新合同**，新合同退租时押金余额可能为 0；
8. **押金台账未收（paid=0）也显示“已收取”**，状态枚举缺少待收/部分收取。

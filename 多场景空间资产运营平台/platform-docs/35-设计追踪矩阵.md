# 设计追踪矩阵

> 用途：确认需求、页面、动作、接口、权限、验收用例之间的对应关系  
> 状态：评审前草案  
> 说明：本矩阵证明“设计有承接”，不代表代码已实现。

---

## 1. 追踪规则

```text
每条要求必须有页面承接
每个页面动作必须有状态变化
每个状态变化必须有接口
每个接口必须有权限
每个关键动作必须有验收用例
```

状态说明：

```text
已覆盖：设计、页面、接口、权限、验收均有对应
待确认：设计已有，接口或口径需评审确认
待实现：设计已明确，代码尚未实现
```

## 3. 五项重点追踪

### 3.1 合同直接收款

| 项 | 内容 |
|---|---|
| 页面 | 合同详情 → 直接收款 |
| 动作 | 选择一笔/多笔账单 → 分配金额 → 确认 |
| 状态 | 账单 未缴/部分缴 → 已缴/部分缴 |
| 接口 | `GET /billing/bills/options`、`POST /billing/bills/{id}/pay` |
| 权限 | `contract:pay`、`billing:pay` |
| 验收 | AC-CON-006 |
| 规则 | 无账单禁用；金额不超未收；多账单生成分配；生成收据 |

## 5. 评审用途

评审时按本矩阵逐条检查：

```text
有没有页面
有没有动作
有没有接口
有没有权限
有没有验收
有没有未确认项
```

矩阵中“待确认/待实现”项不等于设计缺失，而是评审需要明确责任人和完成时间。

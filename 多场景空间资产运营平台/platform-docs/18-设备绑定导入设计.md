# 设备绑定导入设计（借鉴旧系统）

## 1. 模板

文件格式：CSV，UTF-8 带 BOM。

表头：

```text
组织编码,楼栋,单元,楼层,房间,床位内房,房源编号,房源名称,房源类型,建筑面积,设备编号,设备类型,设备名称,物理MAC
```

示例：

```csv
组织编码,楼栋,单元,楼层,房间,床位内房,房源编号,房源名称,房源类型,建筑面积,设备编号,设备类型,设备名称,物理MAC
350600,A栋,1单元,1层,101室,,,101室,公租房,60,,门锁,101门锁,
```

## 2. 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| 组织编码 | 是 | 当前租户项目编码，对应 `bp_org.org_code` |
| 楼栋 | 否 | 创建/复用楼栋空间 |
| 单元 | 否 | 创建/复用单元空间，填写前必须有楼栋 |
| 楼层 | 否 | 创建/复用楼层空间，填写前必须有单元 |
| 房间 | 否 | 创建/复用房间空间，填写前必须有楼层 |
| 床位内房 | 否 | 创建/复用床位空间，填写前必须有房间 |
| 房源编号 | 否 | 为空自动生成 `HS` 编号 |
| 房源名称 | 否 | 为空使用房间/床位名称 |
| 房源类型 | 否 | 空或无法识别时报错；支持中文和编码 |
| 建筑面积 | 否 | 数字，写入房源 |
| 设备编号 | 否 | 为空生成 `DV` 编号 |
| 设备类型 | 有设备时必填 | 支持中文和编码 |
| 设备名称 | 否 | 为空使用设备类型 |
| 物理MAC | 否 | 为空视为虚拟设备，等待安装回填 |

## 3. 房源类型

```text
公租房 / 公共租赁          → PUBLIC_RENTAL
保障性租赁住房 / 保租房    → AFFORDABLE_RENTAL
人才公寓                   → TALENT_APARTMENT
宿舍                       → DORMITORY
出租房                     → RENTAL
酒店民宿                   → HOTEL
```

## 4. 设备类型

```text
门锁 / 智能锁 → LOCK
门禁           → ACCESS
道闸           → BARRIER
电梯           → ELEVATOR
水表           → WATER_METER
电表           → ELEC_METER
燃气表 / 气表  → GAS_METER
热量表         → HEAT_METER
摄像头 / 视频  → CAMERA
传感器         → SENSOR
车锁           → CAR_LOCK
控制主机       → CONTROLLER
其他           → OTHER
```

## 5. 导入规则

```text
一行一台设备
同一空间多行自动归并
楼栋/单元/楼层/房间/床位逐级创建
填写下级前必须填写上级
房间存在时自动创建房源
同一个空间只创建一个房源
房源编号为空自动生成 HS 编号
设备编号为空自动生成 DV 编号
设备编号重复：
  同一空间 → 跳过
  其他空间 → 报错
物理 MAC 不允许重复
物理 MAC 为空 → 虚拟设备，状态 PENDING_INSTALL
物理 MAC 有值 → 已安装，状态 INSTALLED
一个设备同一时间只绑定一个空间
失败行返回行号和原因，不中断整批
```

## 6. 导入结果

```text
total           总行数
spacesCreated   新增空间数
housesCreated   新增房源数
devicesCreated  新增设备数
devicesBound    成功处理设备数
failed          失败行数
errors          行号和原因
```

```text
POST /api/v1/platform/devices/import
Content-Type: multipart/form-data
字段：file
```

## 9. 与旧系统的对应

旧系统字段和规则已保留：

```text
组织编码
楼栋
单元
楼层
房间
床位内房
房源编号
房源名称
房源类型
建筑面积
设备编号
设备类型
设备名称
物理MAC
```

新增系统能力：

```text
导入结果统计
失败行明细
设备 MAC 唯一校验
虚拟设备状态
安装状态
项目级组织编码校验
```

旧系统只创建房源和设备；新系统同时保留空间层级、房源、设备绑定和继承关系。

# 全页面数据操作与选择器审计

> 审计日期：2026-11-09  
> 范围：54 个 Vue 页面、48 个 `/guarantee/*` 路由  
> 方式：静态扫描 + 关键 UI 流程实测  
> 结论：页面可用，但“搜索选择器、主数据编辑/归档、表格检索”明显不足

---

## 1. 总体结论

```text
页面按钮：全部按钮都有点击处理函数，未发现死按钮
关键流程：申请/合同/账单/房源产品化已真实点击通过
选择器：91 个下拉全部是原生 select，0 个搜索/远程/树形选择器
表格检索：大多数页面没有页内搜索、筛选或分页
主数据：新增较多，编辑/归档/删除明显不足
```

一句话：

```text
“能点、能提交流程”基本成立
“数据管理得好用”还不成立
```

## 5. 按钮审计

### 5.1 静态结果

```text
所有模板 @click 均能对应到已定义函数
未发现“点击无处理函数”的死按钮
```

### 5.2 运行结果

已真实点击通过：

```text
申请新增/提交/驳回
合同草稿/提交/审批/生效
账单生成/收款/退款
房源展示/发布/预约/订单/支付/转合同
轮候/配租
```

### 5.3 仍存在的按钮风险

```text
1. 多数按钮没有 :disabled="busy"，快速双击可能重复提交
2. 作废/移除/取消等破坏性操作，部分没有二次确认
3. 按钮是否可见依赖 can/canAction，部分页面仍只按菜单判断
4. 只读页面缺失处理按钮，不一定是 bug，但角色会问“为什么不能操作”
```

```text

```

## 8. 结论

```text
业务流程状态机：基本闭环
按钮连线：未发现死按钮
数据管理体验：不足
选择器：最大的短板
```

建议下一阶段先做：

```text
统一 SearchSelect + TreeSelect 组件
再逐页替换项目/人员/房屋/合同/账单/空间选择器
最后补主数据编辑与归档
```

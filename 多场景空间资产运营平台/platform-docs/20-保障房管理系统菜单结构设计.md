# 保障房管理系统菜单结构设计

> 依据：多场景平台总体设计基线 v1.1  
> 范围：保障房场景业务菜单与场景配置菜单  
> 原则：不沿用旧系统菜单组合，按业务对象和业务生命周期重新组织

---

## 1. 设计原则

### 1.1 按业务生命周期组织

```text
申请
→ 资格
→ 轮候
→ 配租
→ 合同
→ 入住
→ 账单
→ 收费
→ 服务
→ 年审
→ 退租
```

菜单按阶段分组，不按旧系统的部门或功能堆叠。

### 1.2 菜单只放业务能力

```text
列表页
任务页
看板页
报表页
配置页
```

不放：

```text
新增
编辑
删除
详情
审批动作
```

这些是页面内动作，不单独占菜单。

### 1.3 最多三级

```text
一级：业务域
二级：业务页面
三级：仅配置类或报表类需要时使用
```

业务页面原则上不超过两级。

### 1.4 平台菜单与场景菜单分离

```text
平台控制台
├─ 租户
├─ 组织
├─ 用户
├─ 角色
├─ 权限
├─ 菜单
├─ 字典
├─ 行政区划
├─ 平台审批模板
├─ IoT 设备模型
├─ 开放平台
└─ 审计

保障房场景
├─ 业务菜单
└─ 场景配置
```

保障房菜单不重复放平台级用户、角色、权限、行政区划。

### 1.5 菜单可见不等于数据可见

```text
菜单按角色显示
数据按数据范围过滤
字段按字段权限脱敏
```

## 2. 总体菜单结构

```text
工作台
申请与资格
轮候与配租
合同与入住
账单与收费
房源与资产
住户与档案
服务与监督
设备与通行
────────────────
场景配置（管理菜单，底部单独区域）
```

业务菜单 9 组，管理菜单 1 组。

## 3. 菜单明细

### 3.1 工作台

| 二级菜单 | 路由 | 页面类型 | 核心内容 |
|---|---|---|---|
| 运营驾驶舱 | `/guarantee/workbench` | 工作台 | 房源、申请、合同、收费、设备、告警 |
| 我的待办 | `/guarantee/todos` | 任务页 | 审批、审核、催缴、告警、年审 |
| 消息中心 | `/guarantee/messages` | 列表 | 系统消息、业务提醒、已读未读 |
| 分析报表 | `/guarantee/reports` | 报表 | 运营、财务、房源、设备、审批 |

驾驶舱要求：

```text
项目筛选
时间范围
指标下钻
待办直达
告警直达
```

### 3.2 申请与资格

| 二级菜单 | 路由 | 页面类型 | 核心动作 |
|---|---|---|---|
| 申请受理 | `/guarantee/applications` | 列表 + 向导 | 新增、暂存、提交、导入、查看 |
| 资格审核 | `/guarantee/applications/review` | 任务页 | 通过、驳回、退回补充、转办 |

申请详情不单独做菜单，从列表进入。

必须覆盖：

```text
草稿
提交
审核中
通过
驳回
退回补充
转轮候
```

### 3.3 轮候与配租

| 二级菜单 | 路由 | 页面类型 | 核心动作 |
|---|---|---|---|
| 轮候管理 | `/guarantee/waitlist` | 列表 + 看板 | 入队、调序、冻结、取消、转配租 |
| 配租管理 | `/guarantee/allocation` | 看板 + 向导 | 批次、选房、配租、取消、结果 |

配租管理内部页签：

```text
配租批次
配租执行
配租结果
```

不把“批次、执行、结果”拆成三个菜单。

| 入住办理 | `/guarantee/occupancy` | 办理页 | 验房、交钥匙、设备授权、入住确认 |
| 退租管理 | `/guarantee/terminations` | 列表 + 办理 | 退租申请、结算、验房、释放房源 |

合同详情页签：

```text
概览
账单与收款
同住人
设备与授权
附件
变更记录
审批记录
操作日志

### 3.5 账单与收费

| 二级菜单 | 路由 | 页面类型 | 核心动作 |
|---|---|---|---|

```

### 4.3 旧路径处理

新设计不再保留旧菜单组合，也不要求旧路径进入新系统菜单。

```text
正式路由只使用 /guarantee/*
旧路径不作为新设计、菜单、权限、验收依据
旧菜单组合不再复现
```

如上线初期需要兼容少量历史书签，可由网关或前端做临时重定向：

```text
临时重定向
不进菜单
不配权限
不纳入验收
不作为长期设计
```

保障房正式菜单和页面统一使用 `/guarantee/*`。

## 7. 菜单交互

### 7.1 顶部

```text
场景切换
项目切换
全局搜索
待办角标
消息角标
帮助
个人中心
```

### 7.2 左侧

```text
一级分组可折叠
二级菜单
当前项高亮
分组徽标：待办数、逾期数、告警数
最近访问
收藏
```

### 7.3 默认首页

```text
按角色设置默认首页
场景管理员/领导 → 运营驾驶舱
窗口受理 → 申请受理
审核员 → 资格审核
财务 → 账单中心
客服 → 投诉建议
运维 → 设备事件
```

### 7.4 层级控制

```text
业务菜单最多两级
配置和报表允许三级
不把 CRUD 拆成三级菜单
```

## 9. 不推荐的做法

```text
按旧系统 8 组原样复制
一个功能一个菜单
新增/编辑/删除单独占菜单
详情页单独占菜单
同一业务在多个分组重复出现
把平台用户/角色/权限放进保障房菜单
把配置菜单开放给普通经办人
菜单层级超过三级
```

---

## 10. 验收标准

```text
1. 业务菜单不超过 9 组
2. 业务页面原则上两级
3. 不出现旧系统菜单组合
4. 每个页面有明确业务动作
5. 每个列表可进入详情
6. 每个角色只看到授权菜单
7. 财务菜单可见但数据按组织树过滤
8. 项目管理员不能跨项目看人员
9. 设备绑定、合同详情、账单收费符合标准页面
10. 旧路径不作为新设计输入
```

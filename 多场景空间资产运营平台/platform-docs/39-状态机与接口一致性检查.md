# 状态机与接口一致性检查

> 目的：核对阶段 1 的状态/动作矩阵与阶段 2 的接口契约是否一一对应  
> 说明：发现的是设计契约缺口，不代表代码缺陷。

---

## 1. 检查方法

```text
逐对象列出状态和动作
逐个动作查找接口
检查接口权限
检查状态前置条件
检查幂等/并发要求
```

检查对象：

```text
申请
合同
账单
设备
审批
草稿
```

## 7. 缺口清单

| 编号 | 缺口 | 影响 | 优先级 | 建议 |
|---|---|---|---|---|
| GAP-01 | 申请草稿删除接口 | 草稿无法清理 | 中 | 增加 DELETE 或作废 |
| GAP-02 | 申请关闭接口 | 已签约申请无法归档 | 中 | 增加 close |
| GAP-03 | 配租创建/取消接口未明确 | 申请→配租链路断 | 高 | 补 allocation API |
| GAP-04 | 合同审批撤回接口 | 审批中无法撤回 | 高 | 增加 withdraw |
| GAP-05 | 合同草稿删除接口 | 草稿无法清理 | 中 | 增加 DELETE/作废 |
| GAP-06 | 合同设备授权接口 | 合同详情授权无入口 | 中 | 复用授权 API 或增加 |
| GAP-07 | 账单草稿编辑/删除 | 草稿无法维护 | 低 | 增加 update/delete |
| GAP-08 | 账单关闭接口 | 减免后无法归档 | 低 | 增加 close |
| GAP-09 | 设备报修接口 | 故障无法转工单 | 中 | 对接工单 |
| GAP-10 | 设备启用接口 | 停用设备无法恢复 | 中 | 增加 enable |

## 8. 并发与幂等检查

### 8.1 配租

```text
同一房源并发配租
需要唯一约束/乐观锁
失败方必须提示冲突
```

### 8.2 收款

```text
同一账单并发收款
需要账单版本或行锁
重复提交需要幂等键
```

### 8.3 设备绑定

```text
同一设备并发绑定
需要唯一约束
一个设备只允许一个空间
```

### 8.4 批量生成

```text
重复点击生成
需要任务幂等键
需要重复账单校验
```

## 9. 结论

```text
主流程动作—接口基本一致
发现 10 个契约缺口
其中 GAP-03、GAP-04 为高优先级
并发/幂等要求已明确，但需实现约束
```

评审时需要决定：

```text
删除/关闭是接口还是作废
合同设备授权复用哪个接口
配租取消是否单独接口
设备报修是否走工单
```

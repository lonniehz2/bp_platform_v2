# 通用设计与交付原则

> 目的：避免“按钮做了、功能看起来有了、结果还是错的”，减少返工。
> 适用：页面、模板、导出、打印、接口、数据、权限、版本管理。

## 0. 先定义“用户真正要的结果”

不要从用户说的控件出发，要先确认结果。

示例：

```text
用户说：页面尺寸能不能选 A5？
真正要的结果：
选择 A5 后，设计画布、保存配置、PDF 预览、正式 PDF 全部是 A5。
```

如果意图不明确，先确认，不靠猜测实现。

## 1. 端到端原则

任何功能必须覆盖完整链路：

```text
UI 操作
→ 前端状态
→ 保存接口
→ 数据库/文件
→ 重新加载
→ 预览/导出/打印
→ 失败提示
```

只完成 UI 控件不算完成。

## 2. 可见反馈原则

用户执行操作后，必须能看到明确变化。

反例：

```text
点击“编辑”后，数据回填到屏幕外，用户看不到任何反应。
```

正确：

```text
打开编辑弹窗，或滚动到编辑区并高亮当前状态。
```

## 3. 所见即所得原则

编辑器预览必须使用最终输出同一套数据。

反例：

```text
画布是 A5，下载 PDF 是 A4。
```

正确：

```text
设计画布、页面尺寸、字段位置、印章位置、PDF 输出使用同一份 canvas_json/pageSize。
```

## 4. 预览不等于下载

预览的目的，是让用户在提交前确认结果。

正确：

```text
页面内 iframe/PDF 查看器直接显示
用户确认后再下载或发布
```

错误：

```text
点“预览”直接下载文件
```

## 5. 单一编辑入口

同一对象不要保留多个相互冲突的编辑入口。

反例：

```text
模板列表有“编辑”
模板设计器也能编辑
两套保存逻辑不一致
```

正确：

```text
保留一个权威编辑器
其他入口只负责跳转、查看、发布
```

## 6. 可逆原则

编辑器和业务对象都必须可恢复。

编辑器：

```text
Ctrl + Z
Ctrl + Y
撤回/重做按钮
```

数据：

```text
版本历史
恢复旧版本
回滚
```

没有恢复能力的高风险操作，必须二次确认。

## 7. 版本号不可复用

版本号是历史身份，不是简单计数器。

正确：

```text
回滚到 v8
列表先显示 v8
再次修改发布
新版本 = 历史最大版本 + 1 = v10
```

错误：

```text
回滚到 v8 后重新生成 v9
历史里出现两个 v9，无法区分
```

规则：

```text
回滚只改变内容
新发布版本号 = max(当前版本, 历史最大版本) + 1
```

## 8. 历史与当前分离

必须明确：

```text
历史收据是否冻结生成时模板
还是每次下载使用最新模板
```

当前策略如果是“使用最新模板”，必须保证：

```text
旧文档的 template_id 会同步
不会静默回退到旧固定格式
```

如果是“冻结历史模板”，则：

```text
收据生成时固化 template_id + template_version
后续修改模板不影响历史收据
```

两种策略只能选一种，不能模糊。

## 9. 输出一致性原则

同一个业务对象在不同出口必须一致：

```text
页面
PDF
打印
导出
接口
报表
```

任一出口不同步，都算功能未完成。

## 10. 失败显式原则

不允许静默失败或静默降级。

错误示例：

```text
模板渲染失败
→ 自动使用旧格式
→ 用户以为新模板生效
```

正确：

```text
明确报错
或明确提示“已回退到默认模板”
```

## 11. 测试是交付的一部分

每个功能至少要有：

```text
操作前状态
操作动作
可见变化
保存后重新进入
后端/数据库结果
导出/预览结果
异常路径
```

能用断言验证的，不靠肉眼。

## 12. 不做半成品

不允许：

```text
只加按钮不接逻辑
只改前端不改后端
只改保存不改读取
只改预览不改正式输出
```

如果只能完成一部分，必须明确说明未完成部分。

## 13. 需求澄清模板

实现前先回答：

```text
用户要的最终结果是什么？
在哪个页面能看到？
哪些数据要保存？
刷新后是否还要保留？
哪些输出必须同步？
失败时用户看到什么？
哪些角色/项目可见？
如何验证？
```

## 14. 完成定义（Definition of Done）

```text
[ ] 用户能看到变化
[ ] 可以保存
[ ] 刷新/重新进入后仍存在
[ ] 预览与实际输出一致
[ ] PDF/导出/打印同步
[ ] 失败有明确提示
[ ] 权限/数据范围正确
[ ] 有验证记录
```

## 15. 评审检查清单

```text
[ ] 这是用户要的结果，还是字面控件？
[ ] 前端、后端、数据库、输出是否全链路？
[ ] 是否存在两个编辑入口？
[ ] 是否有撤销/回退？
[ ] 版本号是否可能重复？
[ ] 旧数据是否会静默回退？
[ ] 预览是否真的显示结果？
[ ] 刷新后是否仍然正确？
[ ] 失败是否可见？
[ ] 是否有验收用例？
```

## 16. 最近案例复盘

### 页面尺寸

```text
只改下拉框 → 画布不变 = 未完成
画布变了 → PDF 不变 = 未完成
```

### 模板预览

```text
预览按钮触发下载 = 未完成
必须在页面内直接显示
```

### 编辑入口

```text
设计器和普通编辑两套逻辑 = 设计缺陷
保留一个权威入口
```

### 版本回滚

```text
回滚后复用旧版本号 = 历史冲突
必须 max+1
```

### 编辑器

```text
没有 Ctrl+Z = 基础能力缺失
```

## 一句话

> 用户要的不是“一个按钮”，而是“按钮背后可验证、可保存、可恢复、可输出的完整结果”。

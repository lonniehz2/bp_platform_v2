# 设备授权策略与 IoT 同步开发任务清单

> 依据：`57-设备授权策略与IoT同步任务设计.md`  
> 状态：任务拆分稿，未编码  
> 原则：先只读接入，再写授权；先单项目灰度，再全量

---

## 1. 执行原则

```text
1. 先确认 IoT 接口，再写业务代码
2. 先只读快照，再写授权
3. 先影子同步，再真实下发
4. 单项目灰度，验证后全量
5. 所有写操作可重试、可审计、可回滚
```

---

## 2. 任务总览

| 阶段 | 内容 | 关键产出 |
|---|---|---|
| P0 | IoT 能力确认 | 接口清单、能力矩阵 |
| P1 | 数据层 | 策略表、映射表、同步任务表 |
| P2 | 后端 | 策略解析、计划生成、IoT 适配、冻结任务 |
| P3 | 前端 | 项目策略、合同状态、设备授权、二级管理员 |
| P4 | 测试 | 单元、集成、离线、权限、回归 |
| P5 | 灰度上线 | 影子模式、试点、监控、回滚 |

## 10. 第一批建议任务

建议第一个迭代只做：

```text
T0.1 IoT 接口确认
T0.2 账号/设备映射
T1.1 项目策略表
T1.2 合同快照
T2.1 项目策略 API
T2.2 合同快照
T2.3 策略解析
```

先不做真实下发，只输出 Desired Plan 并做影子对比。

这样可以先验证：

```text
三种租赁模式解析是否正确
合同授权时间是否正确
短租/长租是否区分
```

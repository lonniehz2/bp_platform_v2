# 人员、资产、设备关系与批量导入设计

> 状态：设计稿 v1.1，未编码  
> 范围：人员、房屋、设备、关系、授权、合同、迁移导入  
> 关键决策：车位本期不做；人员-设备授权保留且独立生效；导入支持跳过/覆盖；5000 行以上异步  
> v1.1 修订：设备四级权限以 IoT 为准；业务系统保存策略和同步状态，不重复建四级授权树。详见第 14 节。

---

## 1. 设计结论

### 1.1 四类对象

```text
人员
资产（当前为房屋，未来扩展车位）
设备
合同
```

### 1.2 五类关系

```text
人员-资产关系       承租人、家庭成员、产权人
人员-资产通行授权   人员对空间/房屋的权限
人员-设备通行授权   临时人员对单台设备的权限
设备-资产绑定       设备安装在哪个空间
合同                人员与资产的租赁关系
```

### 1.3 核心原则

```text
对象导入和关系导入分开
关系导入使用业务编码，不使用数据库 ID
人员-设备授权独立存在，不强制依赖空间授权
设备授权必须有起止日期
导入冲突由用户选择跳过或覆盖
5000 行以上走异步任务
```

## 2. 领域模型

```text
人员 Person
  │
  ├── 人员-资产关系 PersonAssetRelation
  │        └── 资产 Asset
  │
  ├── 合同 Contract
  │        └── 资产 Asset
  │
  ├── 空间授权 AccessGrant(targetType=SPACE)
  │        └── 空间 Space
  │
  └── 设备授权 AccessGrant(targetType=DEVICE)
           └── 设备 Device
                    │
                    └── 设备-资产绑定 DeviceBinding
                             └── 空间 Space
```

### 2.1 概念区分

| 概念 | 回答的问题 | 示例 |
|---|---|---|
| 人员-资产关系 | 这个人跟这个资产是什么关系 | 承租人、家庭成员、产权人 |
| 合同 | 这个人和这个资产签了什么租约 | 月租、押金、起止日期 |
| 空间授权 | 这个人能进哪些空间 | A栋、1单元、101 |
| 设备授权 | 这个人能操作哪台设备 | 某台临时门锁 |
| 设备绑定 | 这台设备装在哪里 | 门锁装在 101 |

### 2.2 生效规则

```text
空间授权：人员对目标空间及其绑定设备生效
设备授权：只对指定设备生效，不要求空间授权
最终权限：空间授权 ∪ 设备授权
```

说明：

```text
临时人员可以只授权某台设备
不需要先给他一个空间权限
这正是不强制“人员-资产”授权的原因
```

## 3. 权限模型

### 3.1 权限等级

统一使用四级权限：

| 代码 | 名称 | 含义 |
|---|---|---|
| OWNER | 所有权 | 产权人级别，最高 |
| MANAGER | 管理权 | 可管理资产/设备 |
| USER | 使用权 | 正常使用 |
| VISITOR | 访客权 | 临时访问，权限最低 |

现有 `OPEN` 建议映射为：

```text
OPEN → USER
```

迁移时需在数据字典中明确。

### 3.2 授权对象

```text
SPACE    空间/房屋
DEVICE   单台设备
```

人员-设备授权：

```text
targetType = DEVICE
validStart 必填
validEnd 必填
```

人员-空间授权：

```text
targetType = SPACE
validStart 必填
validEnd 可为空（长期）
```

### 3.3 重叠规则

```text
同一人员 + 同一对象 + 有效期重叠
默认视为重复，跳过或覆盖由导入选项决定
```

## 4. 车位模型

### 4.1 本期范围

```text
本期不实现车位
本期只做房屋
```

### 4.2 未来模型

智慧停车阶段按空间层级建模：

```text
小区
  └── 期/苑
        └── 车库/车场
              └── 车位
```

车位与房屋一样：

```text
作为人员拥有的资产
可签合同
可绑定设备
可授权
可计费
```

### 4.3 预留要求

```text
资产表保留 assetTypeCode
空间类型预留 PARKING 扩展
设备绑定仍按 spaceId
合同仍按 houseId/assetId
```

## 5. 批量导入中心

### 5.1 入口

统一入口：

```text
数据导入中心

基础数据
  人员
  房屋/资产
  设备
  用户

关系数据
  人员-资产关系
  人员-设备授权
  人员-空间授权
  设备-资产绑定
  合同

迁移导入
  人员+资产+设备+授权复合模板

导入记录
  进行中
  成功
  部分成功
  失败
```

列表页保留快捷入口，但共用同一后端服务。

### 5.2 导入流程

```text
1. 选择导入类型
2. 下载模板
3. 上传文件
4. 选择冲突策略：跳过（默认）/ 覆盖
5. 系统校验并预览
6. 确认提交
7. 异步执行
8. 下载结果和错误行
```

### 5.3 异步任务

支持 5000 行以上：

```text
任务状态：PENDING / VALIDATING / READY / IMPORTING / DONE / FAILED
进度：已处理行数 / 总行数
结果：成功数、跳过数、失败数
错误文件：行号、字段、原因
```

接口建议：

```text
GET  /imports/{entity}/template
POST /imports/{entity}/validate
POST /imports/{entity}/commit
GET  /imports/jobs/{jobId}
GET  /imports/jobs/{jobId}/errors
```

### 5.4 冲突策略

用户在导入时选择：

```text
跳过（默认）
覆盖
```

规则：

| 类型 | 跳过 | 覆盖 |
|---|---|---|
| 人员 | 保留原数据 | 更新允许字段 |
| 房屋/资产 | 保留原数据 | 更新名称/面积/状态 |
| 设备 | 保留原数据 | 更新名称/型号/绑定 |
| 人员-资产关系 | 保留原关系 | 更新关系类型/有效期 |
| 设备绑定 | 保留原绑定 | 重新绑定到新空间 |
| 授权 | 保留原授权 | 结束旧授权并新建 |
| 合同 | 保留原合同 | 仅更新允许字段，不覆盖已生效金额 |

覆盖必须二次确认，并记录审计。

### 6.9 迁移复合模板

用于老系统一次性迁移：

| 字段 | 必填 | 说明 |
|---|---|---|
| projectCode | 是 | 项目编码 |
| personCode | 是 | 人员编码 |
| assetCode | 是 | 房屋/资产编码 |
| relationType | 是 | 人员-资产关系 |
| deviceCodes | 否 | 多台设备，用 `|` 或逗号分隔 |
| grantLevel | 是 | 授权权限 |
| validFrom | 是 | 授权开始 |
| validTo | 是 | 授权结束 |

处理逻辑：

```text
1. 建立人员-资产关系
2. 绑定 deviceCodes 到 asset
3. 建立人员-空间授权
4. 如 deviceCodes 非空，同时建立人员-设备授权
5. 单行全部成功或失败
```

说明：

```text
复合模板中的授权只包含期限和权限
不包含合同金额、账单、收据
合同仍需单独导入
```

```text

```

### 7.4 错误报告

```text

字段
错误原因
建议处理
```

示例：


## 8. 事务与一致性

### 8.1 单行事务

```text
复合模板：一行一个事务
任一步失败，该行全部回滚
```

### 8.2 任务事务

```text
允许部分成功
失败行不阻塞其他行
任务结果记录成功/跳过/失败
```

### 8.3 覆盖事务

```text
覆盖授权：先结束旧授权，再创建新授权
覆盖绑定：先解绑旧空间，再绑定新空间
覆盖合同：只更新允许字段
```

### 8.4 审计

```text
记录导入人、时间、文件、任务 ID
记录成功/跳过/失败数量
记录覆盖前的关键字段
```

## 14. v1.1 修订：设备权限与管理员模型

本节优先于前面关于“业务系统保存四级授权链”的描述。

### 14.1 结论

```text
IoT 平台是设备四级权限的主数据源
业务系统保存资产、合同、人员和授权策略
APP/小程序是住户设备操作入口
业务系统不重复建设四级权限树
```

四级权限：

```text
OWNER     所有权
MANAGER   管理权
USER      使用权
VISITOR   访客权
```

### 14.2 三种主体，三种基数

```text
设备所有权：每台设备唯一
主管理员：  每台设备唯一
二级管理员：每台设备多个
通行授权：  每台设备一张共享表
```

不要用一张通用 grant 表承载所有关系。

### 14.3 设备所有权

```text
device_ownership
  device_id       unique
  owner_user_id
  owner_org_id
  acquired_at
  status
```

规则：

```text
所有者唯一
所有者没有开门权限
所有者只有转让/收回管理权的权限
设备绑定资产时，所有权归组织管理员
资产转让时，所有权随资产转让
```

### 14.4 主管理员

```text
device_primary_manager
  device_id       unique
  manager_user_id
  granted_by
  valid_from
  valid_to
  status
```

规则：

```text
主管理员唯一
拥有完整授权管理能力
不能再次转让管理权
可以归还管理权
```

退出路径：

```text
1. 所有权人收回
2. 租赁结束自动归还
3. 主管理员主动提前归还
```

主动归还：

```text
由当前主管理员发起
归还给所有权人/组织管理员
可立即生效或指定生效时间
保留审计记录
```

### 14.5 二级管理员

```text
device_secondary_manager
  id
  device_id
  manager_user_id
  parent_primary_id
  created_by
  valid_from
  valid_to
  status
```

规则：

```text
可以多个
与主管理员拥有相同的设备管理能力
不能创建三级管理员
只能由创建它的主管理员撤销
主管理员变更时级联失效
```

能力边界：

```text
可以管理使用权/访客权
不能转让/归还管理权
不能再委派管理员
```

### 14.6 共享通行授权表

```text
device_access_grant
  id
  device_id
  holder_user_id
  level              USER / VISITOR
  valid_from
  valid_to
  single_use
  granted_by         -- 只做审计
  updated_by
  status
  version
```

核心原则：

```text
授权属于设备
不属于某个管理员
管理员只是操作者
```

因此：

```text
主管理员和二级管理员共同维护同一张授权表
不按管理员分区
设备侧不区分是谁授权的
granted_by 只用于审计
```

约束：

```text
同一设备 + 同一人员，同时只能有一条有效授权
```

### 14.7 撤销规则

```text
撤销主管理员
  → 二级管理员级联失效
  → 使用权/访客权保留

撤销二级管理员
  → 只撤销管理员身份
  → 其授出的使用权/访客权保留

租赁结束
  → 管理权归还
  → 使用权/访客权按合同策略撤销或到期

资产转让
  → 所有权和主管理权一并转移
  → 原二级管理员失效
  → 使用权/访客权默认清空，可显式保留
```

关键变化：

```text
撤销管理员 ≠ 撤销授权
授权是设备级事实
管理员只是操作者
```

### 14.8 设备侧视图

IoT 下发给设备的最终策略只包含：

```text
device_id
holder_user_id
level
valid_from
valid_to
single_use
status
```

不包含：

```text
granted_by
主管理员/二级管理员
管理员层级
```

设备离线缓存同样只缓存最终有效授权。

### 14.9 业务系统职责

业务系统保存：

```text
资产归属
合同
人员/同住人
设备授权策略
二级管理员委派单
IoT 映射
同步状态
授权快照
```

业务系统不保存：

```text
设备四级权限树
设备凭证
开门记录主数据
管理员授权链主数据
```

### 14.10 合同设备策略

合同增加：

```text
deviceAuthMode
  TRANSFER_MANAGEMENT   转移管理权给承租人
  USE_ONLY              只给承租人和同住人使用权

deviceAuthStatus
  ACTIVE
  MANAGER_RETURNED
  MANAGER_RECALLED
  ENDED
```

流程：

```text
合同生效
  → 转移管理权 或 授予使用权
合同终止
  → 归还管理权 或 撤销使用权
```

### 14.11 导入影响

允许导入：

```text
人员
房屋/资产
设备
人员-资产关系
设备-资产绑定
人员-空间授权
人员-设备使用权
人员-设备访客权
二级管理员委派
合同
```

不允许直接导入：

```text

主管理员
```

原因：

```text
所有者唯一，必须走资产归属/转让
主管理员唯一，必须走管理权转移/归还
```

二级管理员导入字段：

```text
projectCode
deviceCode
personCode
creatorPersonCode
validFrom
validTo
```

校验：

```text
设备存在
人员存在
当前主管理员存在
创建人必须是当前主管理员
不能重复委派同一人
不能超过期限上限
```

冲突策略：

```text
所有者冲突：整批失败
主管理员冲突：整批失败
二级管理员重复：跳过/覆盖
使用权/访客权重复：跳过/覆盖
```

### 14.12 仍需确认

```text
1. 主管理员主动归还是否需要所有权人确认？
   建议：不需要确认，通知即可。

2. 租赁仍继续时，主动归还是否保留承租人/同住人使用权？
   建议：保留。

3. 撤销二级管理员时，其授出的使用权/访客权保留？
   建议：保留。

4. 任何有效管理员都可以撤销其他人授出的使用权/访客权？
   建议：是。

5. 资产转让时使用权/访客权默认清空还是保留？
   建议：默认清空，允许显式保留。

6. 同一人员在同一设备上只能有一条有效授权？
   建议：是。
```

### 14.13 实施顺序

```text
1. 冻结业务侧四级授权写入
2. 建立 IoT 账号/设备/组织映射
3. 合同增加设备授权策略
4. 合同生效/终止同步 IoT
5. 资产转让同步所有权和管理权
6. 二级管理员委派单
7. 临时人员设备授权单
8. 只读授权快照和对账
```

### 14.14 结论

```text
所有者唯一
主管理员唯一，可收回/到期归还/主动归还
二级管理员多个，不能再委派
通行授权一张共享表，属于设备
业务系统管策略和单据
IoT 管四级权限和凭证
APP/小程序管住户操作
```

## 16. 设备连接模式与在线判定

### 16.1 结论

在线判定不能用一个统一阈值，必须按设备连接模式区分：

```text
常连接设备：按心跳周期判断
低功耗设备：按唤醒周期 + 宽限期判断
手机中继：连接平台即算在线
```

### 16.2 设备连接模式

```text
ALWAYS_ON       门禁、电梯、常电设备
LOW_POWER_LOCK  电池门锁
LOW_POWER_METER 低功耗表计
MANUAL          仅人工同步设备
```

建议配置：

| 模式 | 连接方式 | 在线判定 |
|---|---|---|
| ALWAYS_ON | 固定心跳 | 连续 N 个心跳周期未收到 |
| LOW_POWER_LOCK | 开门唤醒 + 每 24h 自动唤醒 | 超过预期唤醒时间 + 宽限期 |
| LOW_POWER_METER | 每日/每周上报 | 超过预期上报时间 + 宽限期 |
| MANUAL | 手机中继/人工 | 以最后一次平台连接为准 |

### 16.3 在线状态

```text
CONNECTED   当前保持连接
ONLINE      最近一次连接在预期内
SLEEPING    低功耗设备处于正常休眠
OFFLINE     超过预期连接时间 + 宽限期
UNKNOWN     从未连接或数据不足
```

低功耗门锁在两次唤醒之间应显示 `SLEEPING`，不能显示 `OFFLINE`。

### 16.4 判定公式

常连接设备：

```text
offlineAfter = heartbeatInterval * missedHeartbeatCount
ONLINE if now - lastOnlineAt <= offlineAfter
OFFLINE if now - lastOnlineAt > offlineAfter
```

低功耗设备：

```text
nextExpectedContactAt = lastOnlineAt + wakeInterval
ONLINE/SLEEPING if now <= nextExpectedContactAt + contactGrace
OFFLINE if now > nextExpectedContactAt + contactGrace
```

### 16.5 手机中继

```text
手机连接设备
  ↓
手机连接平台
  ↓
平台记录 lastOnlineAt
  ↓
平台下发签名心跳包
  ↓
手机转发设备
  ↓
设备更新时间和离线租期
```

即使没有业务数据：

```text
也算上线
也刷新离线租期
也携带授权版本和冻结状态
```

手机未连接平台：

```text
不算上线
不刷新平台侧 lastOnlineAt
```

### 16.6 离线租期

```text
offlineValidUntil = min(authTo, lastOnlineAt + offlineLeaseDays)
```

校验：

```text
offlineLeaseDays 必须大于设备预期连接间隔 + 宽限期
```

例如：

```text
门锁每 24h 唤醒
宽限期 2h
离线租期至少 2 天
建议 30 天
```

### 16.7 同步审计

手机中继会话必须记录：

```text

sessionId
startedAt / endedAt
lastOnlineAt

result
```

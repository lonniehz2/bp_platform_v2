# 人员、资产、设备关系与批量导入设计

> 状态：设计稿，未编码  
> 范围：人员、房屋、设备、关系、授权、合同、迁移导入  
> 关键决策：车位本期不做；人员-设备授权保留且独立生效；导入支持跳过/覆盖；5000 行以上异步

---

## 1. 设计结论

### 1.1 四类对象

```text
人员
资产（当前为房屋，未来扩展车位）
设备
合同
```

### 1.2 五类关系

```text
人员-资产关系       承租人、家庭成员、产权人
人员-资产通行授权   人员对空间/房屋的权限
人员-设备通行授权   临时人员对单台设备的权限
设备-资产绑定       设备安装在哪个空间
合同                人员与资产的租赁关系
```

### 1.3 核心原则

```text
对象导入和关系导入分开
关系导入使用业务编码，不使用数据库 ID
人员-设备授权独立存在，不强制依赖空间授权
设备授权必须有起止日期
导入冲突由用户选择跳过或覆盖
5000 行以上走异步任务
```

## 2. 领域模型

```text
人员 Person
  │
  ├── 人员-资产关系 PersonAssetRelation
  │        └── 资产 Asset
  │
  ├── 合同 Contract
  │        └── 资产 Asset
  │
  ├── 空间授权 AccessGrant(targetType=SPACE)
  │        └── 空间 Space
  │
  └── 设备授权 AccessGrant(targetType=DEVICE)
           └── 设备 Device
                    │
                    └── 设备-资产绑定 DeviceBinding
                             └── 空间 Space
```

### 2.1 概念区分

| 概念 | 回答的问题 | 示例 |
|---|---|---|
| 人员-资产关系 | 这个人跟这个资产是什么关系 | 承租人、家庭成员、产权人 |
| 合同 | 这个人和这个资产签了什么租约 | 月租、押金、起止日期 |
| 空间授权 | 这个人能进哪些空间 | A栋、1单元、101 |
| 设备授权 | 这个人能操作哪台设备 | 某台临时门锁 |
| 设备绑定 | 这台设备装在哪里 | 门锁装在 101 |

### 2.2 生效规则

```text
空间授权：人员对目标空间及其绑定设备生效
设备授权：只对指定设备生效，不要求空间授权
最终权限：空间授权 ∪ 设备授权
```

说明：

```text
临时人员可以只授权某台设备
不需要先给他一个空间权限
这正是不强制“人员-资产”授权的原因
```

## 3. 权限模型

### 3.1 权限等级

统一使用四级权限：

| 代码 | 名称 | 含义 |
|---|---|---|
| OWNER | 所有权 | 产权人级别，最高 |
| MANAGER | 管理权 | 可管理资产/设备 |
| USER | 使用权 | 正常使用 |
| VISITOR | 访客权 | 临时访问，权限最低 |

现有 `OPEN` 建议映射为：

```text
OPEN → USER
```

迁移时需在数据字典中明确。

### 3.2 授权对象

```text
SPACE    空间/房屋
DEVICE   单台设备
```

人员-设备授权：

```text
targetType = DEVICE
validStart 必填
validEnd 必填
```

人员-空间授权：

```text
targetType = SPACE
validStart 必填
validEnd 可为空（长期）
```

### 3.3 重叠规则

```text
同一人员 + 同一对象 + 有效期重叠
默认视为重复，跳过或覆盖由导入选项决定
```

## 4. 车位模型

### 4.1 本期范围

```text
本期不实现车位
本期只做房屋
```

### 4.2 未来模型

智慧停车阶段按空间层级建模：

```text
小区
  └── 期/苑
        └── 车库/车场
              └── 车位
```

车位与房屋一样：

```text
作为人员拥有的资产
可签合同
可绑定设备
可授权
可计费
```

### 4.3 预留要求

```text
资产表保留 assetTypeCode
空间类型预留 PARKING 扩展
设备绑定仍按 spaceId
合同仍按 houseId/assetId
```

## 5. 批量导入中心

### 5.1 入口

统一入口：

```text
数据导入中心

基础数据
  人员
  房屋/资产
  设备
  用户

关系数据
  人员-资产关系
  人员-设备授权
  人员-空间授权
  设备-资产绑定
  合同

迁移导入
  人员+资产+设备+授权复合模板

导入记录
  进行中
  成功
  部分成功
  失败
```

列表页保留快捷入口，但共用同一后端服务。

### 5.2 导入流程

```text
1. 选择导入类型
2. 下载模板
3. 上传文件
4. 选择冲突策略：跳过（默认）/ 覆盖
5. 系统校验并预览
6. 确认提交
7. 异步执行
8. 下载结果和错误行
```

### 5.3 异步任务

支持 5000 行以上：

```text
任务状态：PENDING / VALIDATING / READY / IMPORTING / DONE / FAILED
进度：已处理行数 / 总行数
结果：成功数、跳过数、失败数
错误文件：行号、字段、原因
```

接口建议：

```text
GET  /imports/{entity}/template
POST /imports/{entity}/validate
POST /imports/{entity}/commit
GET  /imports/jobs/{jobId}
GET  /imports/jobs/{jobId}/errors
```

### 5.4 冲突策略

用户在导入时选择：

```text
跳过（默认）
覆盖
```

规则：

| 类型 | 跳过 | 覆盖 |
|---|---|---|
| 人员 | 保留原数据 | 更新允许字段 |
| 房屋/资产 | 保留原数据 | 更新名称/面积/状态 |
| 设备 | 保留原数据 | 更新名称/型号/绑定 |
| 人员-资产关系 | 保留原关系 | 更新关系类型/有效期 |
| 设备绑定 | 保留原绑定 | 重新绑定到新空间 |
| 授权 | 保留原授权 | 结束旧授权并新建 |
| 合同 | 保留原合同 | 仅更新允许字段，不覆盖已生效金额 |

覆盖必须二次确认，并记录审计。

personCode
```

| 字段 | 必填 | 说明 |

### 6.3 设备

### 6.5 设备-资产绑定

| 字段 | 必填 | 说明 |
|---|---|---|
| projectCode | 是 | 项目编码 |
| deviceCode | 是 | 设备编码 |
| assetCode | 是 | 空间/房屋编码 |
| effectiveDate | 否 | 生效日期 |

唯一键：

deviceCode
```

### 6.6 人员-空间授权

| 字段 | 必填 | 说明 |
|---|---|---|
| projectCode | 是 | 项目编码 |
| personCode | 是 | 人员编码 |
| spaceCode | 是 | 空间/房屋编码 |
| grantLevel | 是 | OWNER/MANAGER/USER/VISITOR |
| validFrom | 是 | 开始日期 |
| validTo | 否 | 结束日期，空为长期 |

### 6.7 人员-设备授权

| 字段 | 必填 | 说明 |
|---|---|---|
| projectCode | 是 | 项目编码 |

| grantLevel | 是 | OWNER/MANAGER/USER/VISITOR |
| validFrom | 是 | 开始日期 |
| validTo | 是 | 结束日期，必填 |

规则：

```text

不要求人员已有空间授权
有效期必须完整
```

### 6.8 合同

| 字段 | 必填 | 说明 |

| assetCode | 是 | 房屋/资产编码 |
| startDate | 是 | 开始日期 |
| endDate | 是 | 结束日期 |
| monthlyRent | 是 | 月租金 |
| depositAmount | 否 | 押金 |
| billingCycle | 否 | MONTH/QUARTER/YEAR |
| billDay | 否 | 账单日 |

合同导入不自动创建通行授权。

### 6.9 迁移复合模板

用于老系统一次性迁移：

| 字段 | 必填 | 说明 |
|---|---|---|
| projectCode | 是 | 项目编码 |
| personCode | 是 | 人员编码 |
| assetCode | 是 | 房屋/资产编码 |
| relationType | 是 | 人员-资产关系 |
| deviceCodes | 否 | 多台设备，用 `|` 或逗号分隔 |
| grantLevel | 是 | 授权权限 |
| validFrom | 是 | 授权开始 |
| validTo | 是 | 授权结束 |

处理逻辑：

```text
1. 建立人员-资产关系
2. 绑定 deviceCodes 到 asset
3. 建立人员-空间授权
4. 如 deviceCodes 非空，同时建立人员-设备授权
5. 单行全部成功或失败
```

说明：

```text
复合模板中的授权只包含期限和权限
不包含合同金额、账单、收据
合同仍需单独导入
```

## 7. 校验规则

### 7.1 对象校验

```text
personCode 存在
spaceCode 存在
deviceCode 存在
projectCode 存在
```

### 7.2 关系校验

```text
人员与项目匹配
资产与项目匹配
设备与项目匹配
设备绑定空间与资产匹配
授权对象类型合法
授权等级合法
授权起止日期合法
```

### 7.3 冲突校验

```text
人员编码重复
空间编码重复
设备编码重复
人员-资产关系重复
设备已绑定其他空间
人员已有有效授权
合同编号重复
```

### 7.4 错误报告

```text
行号
字段
错误原因
建议处理
```

示例：

```text
第 12 行：personCode=P0001 不存在
第 18 行：assetCode=A-101 不属于项目 P01
第 22 行：deviceCode=LOCK-01 已绑定到 A-102
第 25 行：人员-资产关系重复
第 30 行：设备授权 validTo 不能为空
```

## 8. 事务与一致性

### 8.1 单行事务

```text
复合模板：一行一个事务
任一步失败，该行全部回滚
```

### 8.2 任务事务

```text
允许部分成功
失败行不阻塞其他行
任务结果记录成功/跳过/失败
```

### 8.3 覆盖事务

```text
覆盖授权：先结束旧授权，再创建新授权
覆盖绑定：先解绑旧空间，再绑定新空间
覆盖合同：只更新允许字段
```

### 8.4 审计

```text
记录导入人、时间、文件、任务 ID
记录成功/跳过/失败数量
记录覆盖前的关键字段
```

## 12. 需要确认的事项

以下 5 项建议在编码前确认：

### 12.1 授权等级代码

建议：

```text
OWNER / MANAGER / USER / VISITOR
```

现有 `OPEN` 映射为 `USER`。

需确认：

```text
是否采用这组代码
```

### 12.2 空间授权是否继承子空间

建议：

```text
空间授权默认只作用于目标空间
是否继承子空间单独配置
```

需确认：

```text
A栋授权是否自动覆盖 A栋/1单元/101
```

### 12.3 覆盖范围

建议覆盖只更新：

```text
名称、联系方式、面积、型号、有效期、绑定空间
```

不覆盖：

```text
合同金额
已生效账单
历史收款
```

需确认：

```text
是否接受这个覆盖边界
```

### 12.4 文件格式

建议：

```text
CSV + XLSX
5000 行以上异步
```

需确认：

```text
是否首期就支持 XLSX
```

### 12.5 人员-设备授权的业务入口

建议入口：

```text
通行授权中心 → 新增授权 → 对象类型选择“设备”
人员详情 → 授权 Tab → 新增设备授权
```

需确认：

```text
是否需要在设备详情页也提供“授权人员”入口
```

## 13. 结论

```text
人员和设备都是通行授权的主体/对象
人员-设备授权保留，用于临时人员临时授权
人员-资产授权仍保留，用于常规空间权限
设备绑定只负责设备安装位置
导入按“对象 → 关系 → 授权 → 合同”分层
冲突策略由用户选择跳过或覆盖
5000 行以上异步处理
```

这套模型可以同时支持：

```text
常规住户空间授权
临时人员单设备授权
设备安装绑定
老系统关系迁移
未来车位资产
```

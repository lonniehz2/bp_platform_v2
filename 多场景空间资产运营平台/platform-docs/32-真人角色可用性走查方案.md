# 真人角色可用性走查方案

> 类型：正式实现前的真人可用性测试方案  
> 原型：`platform-docs/prototype/standard-pages.html`  
> 重点：合同直接收款多账单分配、驾驶舱期初/当期指标、设备继承来源跳转  
> 说明：真人走查需要真实参与者；本文件是执行方案和记录模板，不代表已执行真人测试。

---

## 1. 走查目标

```text
验证财务能否独立完成合同多账单收款
验证财务/项目负责人能否理解驾驶舱期初与当期口径
验证设备运维能否找到继承设备来源并跳转
发现真实操作中的停顿、误解和错误
```

---

## 2. 参与者

建议至少 6 人：

| 角色 | 人数 | 要求 |
|---|---|---|
| 财务 | 2 | 实际做过账单、收款、减免 |
| 项目负责人 | 2 | 实际做过合同、退租、审批 |
| 设备运维 | 1 | 实际做过设备绑定 |
| 窗口受理/审核员 | 1 | 实际做过申请审核 |

如条件允许，增加 1 名领导和 1 名客服作为观察角色。

---

## 3. 走查形式

```text
一对一会话
45–60 分钟/人
出声思考
主持人 + 记录员
不引导操作
不解释设计
```

环境：

```text
低保真原型
1440×1000 浏览器
测试数据：幸福里保障房项目
```

## 5. 任务卡

### 任务 1：合同直接收款多账单分配

角色：

```text
财务
```

场景：

```text
合同 BC202611001 有 3 笔未结清账单：
BL202611001 未收 900
BL202612001 未收 900
BL202610001 未收 400
```

任务：

```text
请为其中两笔账单收款，第一笔全额，第二笔只收 500 元。
完成后告诉我：本次收了多少、每笔账单还剩多少。
```

观察：

```text
是否先找账单
是否理解可以多选
是否知道默认金额
是否修改金额
是否发现超收限制
是否能找到收据
```

成功标准：

```text
不用帮助完成
正确选择两笔账单
分配金额正确
总金额正确
能说明剩余金额
```

### 任务 2：驾驶舱期初/当期指标

角色：

```text
项目负责人 / 财务
```

任务：

```text
请把驾驶舱切换到“本季账期”。
告诉我：
1. 本期应收是多少
2. 本期实收是多少
3. 期初欠费是多少
4. 本期收缴率是多少
5. 为什么期初欠费不计入本期收缴率
```

观察：

```text
是否找到账期筛选
是否理解“本期/期初”
是否把总欠费当成当期欠费
是否尝试下钻
```

成功标准：

```text
能正确读出 4 个指标
能解释期初不计入本期
不把总欠费误认为当期欠费
```

### 任务 3：设备继承来源

角色：

```text
设备运维
```

任务：

```text
请找到 102 房间继承的门禁设备，告诉我它来自哪个空间。
然后跳转到来源空间，再回到 102。
```

观察：

```text
是否找到“继承设备”页签
是否看到来源空间
是否点击来源空间
是否知道跳转后在哪里
是否能回到原节点
```

成功标准：

```text
能找到继承设备
能说出“来自 A栋/1单元/1层”
能完成来源跳转
能返回 102
```

## 6. 访谈问题

任务后询问：

```text
1. 哪个步骤最费劲？
2. 哪个按钮/字段你一开始没看到？
3. 你觉得“期初欠费”和“当期欠费”区分清楚吗？
4. 多账单收款时，你希望默认全选还是默认不选？
5. 继承来源跳转后，你希望保留返回路径吗？
6. 如果只能改一处，你最想改哪里？
```

## 8. 成功指标

```text
任务完成率 ≥ 80%
任务 1 平均用时 ≤ 3 分钟
任务 2 指标理解正确率 ≥ 80%
任务 3 来源跳转完成率 ≥ 90%
严重误解 = 0
```

满意度：

```text
SEQ（单题满意度）≥ 5/7
```

---

## 9. 问题分级

```text
阻塞：无法完成任务
高：完成但需要帮助或产生错误
中：完成但明显停顿/误解
低：表达或视觉优化
```

## 13. 当前限制

```text
原型是静态 HTML
没有真实接口
没有真实权限
没有真实账单数据
设备树只有演示节点
驾驶舱数据为模拟数据
```

这些限制不影响交互验证，但正式结论需结合真实业务数据复测。

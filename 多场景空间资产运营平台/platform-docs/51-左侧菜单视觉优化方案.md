# 左侧菜单视觉优化方案

> 状态：设计稿，未编码  
> 范围：仅左侧导航，不改业务页面  
> 目标：让一级业务域和二级菜单一眼可分，减少 48 个菜单带来的压迫感

---

## 1. 现状诊断

当前侧边栏：

```text
宽度 210px
10 个业务分组
48 个二级菜单
分组标题 11px
菜单项 14px
```

主要问题：

```text
1. 分组标题太小、太淡，像说明文字，不像一级导航
2. 分组和菜单都用“图标 + 文字”，层级差异弱
3. 菜单项只靠 8px 左边距区分，没有缩进或引导线
4. 多个分组默认展开，滚动长，当前业务域不突出
5. 分组箭头是最右侧的小 “+ / −”，存在感弱
6. 一级图标和二级图标都使用字符符号，风格不统一
7. 折叠成 64px 后只剩图标，没有分组悬浮说明
```

结论：

```text
不是颜色单点问题
是“信息层级 + 导航结构”问题
```

---

## 2. 三个可选方向

### 方案 A：双栏业务导航（推荐）

结构：

```text
左侧 64px 一级业务栏
+ 右侧 208px 当前业务菜单
+ 内容区
```

示意：

```text
┌──────┬────────────────────┬──────────────────────────┐
│  MS  │  申请与资格          │  页面标题                 │
│      │                    │                          │
│  ◈   │  ☷ 申请受理    ●    │  页面内容                 │
│  ☷   │  ♙ 人员档案         │                          │
│  ↕   │  ✓ 年审复核         │                          │
│  ▤   │                    │                          │
│  ¥   │                    │                          │
│  ⌂   │                    │                          │
│  ⚒   │                    │                          │
│  ⌘   │                    │                          │
│  ⚠   │                    │                          │
│  ☰   │                    │                          │
└──────┴────────────────────┴──────────────────────────┘
```

特点：

```text
一级业务域始终可见
二级菜单只显示当前业务域
当前一级项有左侧高亮条
当前二级项有填充胶囊 + 左侧高亮条
48 个菜单不再同时堆在一列
```

适合：

```text
桌面端 1366px 以上
菜单长期继续增加
多场景平台
```

代价：

```text
总宽度从 210px 增加到约 272px
需要改 App 布局和导航状态
```

---

### 方案 B：单栏手风琴强化（低风险）

保持现有单栏，只强化层级：

```text
分组标题：
  12px / 600 / 字距 0.04em
  上下留白 10px
  当前分组文字用品牌蓝

二级菜单：
  左侧缩进 28px
  增加 1px 竖向引导线
  当前项：浅蓝底 + 左侧 3px 蓝条 + 600 字重

分组箭头：
  改为右侧 chevron，展开旋转
```

示意：

```text
┌──────────────────────┐
│ 申请与资格        ⌄  │
│   │ ☷ 申请受理   ●  │
│   │ ♙ 人员档案       │
│   │ ✓ 年审复核       │
│                      │
│ 轮候与配租        ›  │
│ 合同与入住        ›  │
└──────────────────────┘
```

默认只展开当前路由所属分组，其他分组收起。

特点：

```text
改动最小
不增加侧边栏宽度
层级立刻清楚
但仍需要滚动
```

适合：

```text
希望快速优化
暂不改整体布局
```

---

### 方案 C：顶部业务域 + 左侧二级

```text
顶部：工作台 / 保障房 / 资产 / 财务 / 服务 / 配置
左侧：只显示当前业务域的二级菜单
```

特点：

```text
业务域切换最直接
侧边栏最短
适合多场景平台
```

代价：

```text
顶部空间占用增加
一级导航从左侧移到顶部
与当前顶栏、项目选择器需要重新排布
```

## 3. 推荐方案

推荐：

```text
方案 A：双栏业务导航
```

理由：

```text
1. 一级、二级天然分层，不靠字号硬撑
2. 48 个菜单不会同时出现
3. 当前业务域始终有位置感
4. 后续新增菜单不会继续拉长单栏
5. 更适合多场景平台长期扩展
```

降级策略：

```text
宽度 < 1280px：自动切回单栏手风琴（方案 B）
移动端：抽屉式导航
折叠模式：只保留 64px 一级栏，悬浮显示二级
```

## 4. 视觉规范

### 4.1 尺寸

```text
一级栏：64px
二级栏：208px
菜单项高度：40px
分组标题高度：44px
圆角：8px
菜单左右内边距：10px
```

### 4.2 层级

```text
一级：业务域图标 + 名称（二级栏顶部显示）
二级：图标 + 名称
当前一级：左侧 3px 品牌色条 + 淡色底
当前二级：浅蓝胶囊 + 左侧 3px 品牌色条 + 600 字重
```

### 4.3 字体

```text
一级业务名：13px / 600
二级菜单：14px / 400
当前二级：14px / 600
分组辅助说明：11px / 400 / muted
```

### 4.4 颜色

浅色主题：

```text
一级栏底色：#0F172A
一级图标：#94A3B8
一级选中图标：#FFFFFF
一级选中底：#1E293B
二级栏底色：#FFFFFF
当前二级底：#E6F4FF
当前二级文字：#0958D9
引导线：#E5E7EB
```

如果希望保持全浅色：

```text
一级栏底色：#F8FAFC
一级选中底：#E6F4FF
一级选中图标：#1677FF
```

深色主题：

```text
一级栏：#0B1220
二级栏：#111827
当前二级底：#102B45
当前二级文字：#69B1FF
```

### 4.5 图标

```text
统一使用一套线性图标
建议 Lucide / Tabler Icons
尺寸：18px
线宽：1.8
不再混用 ◈ ☷ ♙ ▤ 等字符符号
```

---

## 5. 交互规范

```text
点击一级：切换二级栏，不直接跳页
点击二级：进入页面
当前路由：自动展开对应一级
只允许一个一级处于展开/激活态
再次点击当前一级：可折叠二级栏
折叠模式：点击一级图标，右侧浮出二级菜单
键盘：↑↓ 移动，Enter 进入，Esc 关闭浮层
```

二级栏顶部显示：

```text
业务域名称
当前业务域菜单数量
折叠按钮
```

## 6. 菜单信息架构

建议一级业务域：

```text
工作台
申请与资格
轮候与配租
合同与入住
账单与收费
房源与资产
服务与监督
设备与通行
风险与预警
系统与配置
```

二级菜单沿用现有 48 项，只做归属调整，不新增功能。

---

## 7. 验收标准

```text
1440px 下，一级业务名和二级菜单同时可见
当前一级、当前二级均有明确高亮
任何页面最多 2 次点击到达
48 个菜单不需要在一列中滚动查找
折叠状态有悬浮二级菜单
1280px 以下自动降级为单栏手风琴
角色菜单过滤后，空分组自动隐藏
深色/浅色主题均通过对比度检查
```

---

## 8. 实施建议

```text
第一步：先做静态视觉稿，确认方案 A 或 B
第二步：只改导航组件和 CSS，不改页面
第三步：加折叠/悬浮/键盘交互
第四步：按角色回归菜单可见性
```

不编码前需要确认：

```text
1. 选方案 A、B 还是 C
2. 一级栏用深色还是全浅色
3. 是否接受侧边栏从 210px 增加到约 272px
4. 是否统一换成线性图标库
```

# 平台框架评审清单

> 用途：Phase 0 框架设计评审  
> 评审通过后再进入 ER/DDL 和编码

---

## 1. 场景模型

- [ ] 场景包由平台预置，租户启用
- [ ] 项目/楼栋/资产可设置经营模式
- [ ] 支持混合业态
- [ ] 场景包驱动菜单、角色、模板

建议：

```text
场景包平台预置
租户启用
项目/楼栋/资产可覆盖 business_mode
```

---

## 2. 空间模板

- [ ] 保障房基础 5 级
- [ ] 床位可选
- [ ] 内房可选
- [ ] 内房+床位可选
- [ ] 项目默认模板 + 楼栋覆盖模板
- [ ] 模板版本化

建议：

```text
基础层级 + 可选子级
sub_unit_mode 控制
```

---

## 3. 人员关系

- [ ] 人员主档平台共用
- [ ] 场景关系独立
- [ ] 保障房、物业、酒店、校园不共用一套关系表

建议：

```text
bp_person
bp_person_relation
guarantee_relation
prop_owner_unit
lodging_stay
campus_student
```

---

## 4. 合同/预订/入住

- [ ] 长期合同与短租订单分离
- [ ] 保障房合同走平台合同框架
- [ ] 酒店/民宿走预订/入住
- [ ] 库存日历独立

建议：

```text
bp_contract
bp_booking
bp_stay
bp_inventory_calendar
```

---

## 5. 计费

- [ ] 平台只做计费内核
- [ ] 场景提供计费策略
- [ ] 保障房租金/物业费不写进平台
- [ ] 优惠/补贴区分物业优惠和政府补贴

建议：

```text
bp_billing_kernel
BillingPolicy
bp_discount_*
```

---

## 6. 工作流

- [ ] 平台统一审批
- [ ] 支持多级/会签/或签
- [ ] 场景只提供表单和角色
- [ ] 老保障房审批兼容

建议：

```text
bp_wf_*
```

---

## 7. 设备与授权

- [ ] 设备只做业务资产
- [ ] IOT 负责运行/控制
- [ ] 授权做业务授权
- [ ] 人员钥匙包是授权聚合视图
- [ ] 不做具体凭证

建议：

```text
bp_dev_*
bp_grant_*
```

---

## 8. 菜单与角色

- [ ] 菜单按场景组合
- [ ] 角色模板按场景
- [ ] 不做巨型菜单
- [ ] 支持功能开关

建议：

```text
scene_profile
business_mode
feature_flag
role_template
```

---

## 9. 数据与迁移

- [ ] 新库 bp_platform_v2
- [ ] 老库只读
- [ ] 不做长期双写
- [ ] ID/租户/文件/设备映射明确
- [ ] 迁移校验和回滚明确

---

## 10. 评审结论

```text
通过 / 有条件通过 / 不通过
```

条件：

```text
待补充项
待确认项
负责人
完成时间
```

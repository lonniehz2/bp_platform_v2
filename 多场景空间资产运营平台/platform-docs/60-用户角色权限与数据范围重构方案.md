# 用户、角色、权限与数据范围重构方案

> 状态：设计稿，未编码  
> 目标：消除用户管理、角色管理、菜单管理的重复入口  
> 数据范围规则：角色默认范围取并集，用户例外只能收窄

---

## 1. 当前问题

侧边栏同时存在：

```text
用户与权限
  ├── 用户管理
  ├── 角色管理
  └── 权限清单

独立入口
  ├── 用户管理
  └── 菜单与角色
```

问题：

```text
用户管理重复
角色/菜单管理重复
页面标题重复
职责边界不清
权限和数据范围分散
```

---

## 2. 目标信息架构

只保留一个入口：

```text
系统与数据
  └── 用户与权限
        ├── 用户
        ├── 角色
        └── 权限清单
```

移除侧边栏：

```text
用户管理
菜单与角色
```

```text
/users            → /rbac/users
/menus            → /rbac/roles
/guarantee/users  → /rbac/users
/guarantee/menus  → /rbac/roles
```

用户列表

```

### 角色

```

### 权限清单

```text

```

不在权限清单里做角色分配。

## 4. 权限模型

```text
菜单权限：页面是否可见/可进入
动作权限：按钮和接口，如 user:create、contract:approve
数据范围：能看哪些项目/组织
```

角色绑定：

```text
角色 → 菜单权限 + 动作权限 + 默认数据范围
用户 → 角色 + 数据范围例外
```

最终权限：

```text
用户功能权限 = 所有角色功能权限的并集
用户数据范围 = 角色默认范围并集 ∩ 用户例外
```

---

## 5. 数据范围模型

### 5.1 范围类型

```text
ALL          全部项目
CURRENT      当前项目
PROJECTS     指定项目
ORGS         指定组织
SELF         仅本人
NONE         无数据
```

不要用“空集合”表示全部，必须显式使用 `ALL`。

### 5.2 角色默认范围

角色保存：

```text
dataScopeType
projectIds
orgIds
```

示例：

```text
角色：项目收费员
默认范围：CURRENT

角色：区域财务
默认范围：PROJECTS，项目 A、B、C

角色：稽核员
默认范围：ALL，只读
```

### 5.3 用户例外

用户保存：

```text
scopeOverrideEnabled
dataScopeType
projectIds
orgIds
```

规则：

```text
用户默认继承角色范围
只有需要例外时才开启覆盖
用户例外只能收窄，不能扩大
```

### 5.4 最终范围计算

```text
roleScope = union(所有角色的默认范围)
userScope = 用户例外范围（没有则为 null）
effectiveScope = userScope == null ? roleScope : roleScope ∩ userScope
```

示例：

```text
角色范围：项目 A、B、C
用户例外：项目 B、C
最终范围：项目 B、C
```

```text
角色范围：ALL
用户例外：项目 A
最终范围：项目 A
```

```text
角色范围：项目 A
用户例外：项目 B
最终范围：空，保存时应拒绝
```

### 5.5 校验

保存用户例外时：

```text
用户例外必须是角色范围的子集
不允许通过用户例外扩大角色范围
越界直接报错
```

服务端必须校验，不能只靠前端。

---

## 6. 多角色并集规则

```text
角色 1：项目 A
角色 2：项目 B
角色并集：项目 A、B
用户例外：项目 A
最终：项目 A
```

说明：

```text
并集用于功能权限和数据范围
用户例外只做收窄
```

风险控制：

```text
给用户分配多个宽范围角色时，前端提示最终范围
角色分配需要权限
ALL 范围角色只允许平台管理员分配
```

## 10. 迁移方案

### 第一步：导航去重

```text
删除 users、menus 侧边栏入口
保留 rbac
旧地址重定向
```

### 第二步：页面合并

```text
Users.vue → UserPanel
Menus.vue → RolePanel
新增 PermissionPanel
Rbac.vue 统一壳
```

### 第三步：角色默认范围

```text
新增角色数据范围字段和表
为现有角色设置默认范围
```

### 第四步：用户例外迁移

```text
现有 bp_user_project / bp_user_org 转为用户例外
未设置例外的用户继承角色
```

### 第五步：生效校验

```text
角色范围并集
用户例外收窄
服务端校验越界
```

### 第六步：回归

```text

```

## 14. 页面交互设计

目标：不需要培训，管理员打开页面就知道怎么配。

### 14.1 总体原则

```text
默认简单，高级折叠
用中文业务语言，不直接暴露编码
先给推荐值，再允许自定义
所有危险操作有解释和确认
所有配置都有最终效果预览
```

### 14.2 页面骨架

```text
用户与权限
[用户] [角色] [权限清单]
```

顶部只保留页面标题和 Tab，不再出现重复的“人员档案”“平台角色”。

### 14.3 用户页

列表：

```text
搜索姓名/账号
角色标签
数据范围摘要
状态
操作：编辑 / 角色 / 数据范围 / 启停
```

新增/编辑用户使用右侧抽屉：

```text
基本信息
角色
数据范围
最终权限预览
```

角色选择用卡片，不用裸多选框：

```text
☑ 项目收费员
   可收银、退款、查看本项目账单

☑ 稽核员
   只读查看全部项目
```

数据范围区域：

```text
数据范围
（默认）跟随角色
   当前生效：项目 A、B

[ ] 单独限制
   只能选择角色范围内的项目/组织
```

说明文案：

```text
不设置时，自动继承角色范围。
设置后只能缩小，不能扩大。
```

最终权限预览：

```text
最终可访问：账单、收款、报表
最终可见项目：项目 B、C
最终动作：收款、退款
```

### 14.4 角色页

左侧角色列表，右侧角色详情。

新建角色：

```text
从模板新建
  ├── 项目收费员
  ├── 稽核员
  ├── 资产管理员
  └── 空白角色
```

角色详情：

```text
基本信息
菜单与动作权限
默认数据范围
成员
```

权限分配采用“模块 + 三档预设”：

```text
账单
  ○ 无权限
  ○ 只读
  ○ 管理

合同
  ○ 无权限
  ○ 只读
  ○ 管理
```

高级展开后才显示具体动作：

```text
账单
  ☑ 查看
  ☑ 收款
  ☑ 退款
  ☐ 作废
```

避免一上来展示几十个复选框。

### 14.5 默认数据范围

用单选卡片，不用下拉：

```text
默认可见范围

○ 全部项目
○ 当前项目
○ 指定项目
○ 指定组织
○ 仅本人
○ 无数据
```

选择“指定项目/组织”后出现搜索选择器，已选项用标签展示。

选择“全部项目”时提示：

```text
该角色可访问全部项目，请确认。
```

### 14.6 权限清单

只读，按模块分组：

```text
账单
  账单查看       billing:view
  收款           billing:pay
  退款           billing:refund
```

每项显示：

```text
中文名称
权限编码
说明
被哪些角色使用
```

支持搜索，不支持在这里改角色。

### 14.7 防错设计

```text
用户例外超出角色范围 → 禁止选择并提示
角色被用户使用 → 删除时提示成员数量
扩大范围到全部项目 → 二次确认
未保存离开 → 提示
保存成功 → toast
保存失败 → 字段级错误
```

### 14.8 诊断入口

用户详情增加：

```text
为什么看不到某个页面？
```

展示：

```text
角色是否包含菜单
动作权限是否包含按钮
数据范围是否覆盖项目
```

这是“无需培训”的关键：管理员能自己定位问题。

### 14.9 空状态

```text
暂无用户 → [新增用户]
暂无角色 → [从模板新建角色]
暂无权限 → 提示检查菜单配置
```

### 14.10 移动端

```text
Tab 横向滚动
列表变卡片
编辑用全屏抽屉
保存按钮固定在底部
```

### 14.11 验收

```text
新管理员不看文档能完成：
1. 新建用户
2. 分配角色
3. 限制到一个项目
4. 查看最终权限
5. 新建角色
6. 给角色配账单权限
7. 删除未被使用的角色
```

# 房源产品化与线上展示设计

> 状态：设计草案  
> 范围：房源配置、房源素材、房源发布、线上展示、预约与订单的领域设计  
> 说明：本文件只做设计，不进入编码；首批五个参考页面不实现本模块

---

## 1. 设计目标

把“物理房源”扩展为可展示、可推广、可预约、可交易的“房源产品”，同时不污染当前房源主表和保障房核心业务。

目标：

```text
房源可配置
内容可管理
房源可发布
渠道可扩展
价格可管理
库存可查询
预约可跟踪
订单可承接
```

非目标（当前阶段）：

```text
不实现线上下单
不实现支付
不实现渠道对接
不实现 VR 拍摄
不进入首批五个参考页面
```

## 9. 保障房与市场化房源的区别

### 9.1 保障房

```text
可以线上展示
可以预约看房
不能直接线上下单配租
仍走资格审核、轮候、配租
```

### 9.2 人才公寓、市场化租赁、短租

```text
可以线上展示
可以预约
可以下单
可以支付
可以签合同
```

### 9.3 规则

```text
保障房配租规则不能被线上下单替代
线上展示只是入口
资格、轮候、配租仍是保障房核心流程
```

## 15. 风险

```text
把配置直接写进房源主表
把展示数据当内部资产数据
把保障房配租做成线上下单
公开接口泄露业主信息
图片未经审核直接发布
价格和库存不一致
订单绕过合同和账单
```

## 17. 结论

房源配置和线上展示应该纳入总体设计，但作为独立模块分阶段实现。

```text
现在做领域设计和边界
不进入首批五个参考页面
不直接修改房源主表
不把保障房配租改成线上下单
```

这样后续可以支撑：

```text
房源展示
线上推广
预约看房
线上下单
合同与收款
```

同时不影响当前保障房核心业务设计。

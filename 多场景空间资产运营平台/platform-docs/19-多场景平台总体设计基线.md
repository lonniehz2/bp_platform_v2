## 1. 目标、约束与设计原则

### 1.1 总目标

建设一个支持多场景、多租户、统一权限、统一审批、统一设备能力的空间资产运营平台。

目标不是“把页面做出来”，而是：

```text
业务能闭环
数据能可信
权限能控制
系统能扩展
运营能持续
```

### 1.2 八项核心目标

```text
1. 多场景可扩展
2. 业务闭环
3. 操作简单好用
4. 显示全面可读
5. 安全合规可审计
6. 数据准确一致
7. 稳定高效可运维
8. 可持续交付与演进
```

目标说明：

| 目标 | 含义 | 不是 |
|---|---|---|
| 多场景可扩展 | 新增场景复用平台能力，不复制核心代码 | 不是每个场景各做一套 |
| 业务闭环 | 每个业务对象有状态、动作、结果和日志 | 不是只有列表和新增 |
| 操作简单好用 | 选择、填写、提交、处理都顺畅 | 不是控件越少越好 |
| 显示全面可读 | 关键字段、状态、关联信息完整 | 不是字段堆得越多越好 |
| 安全合规可审计 | 授权、脱敏、审计、留痕 | 不是只做登录 |
| 数据准确一致 | 同一对象一个事实来源，同一指标一个口径 | 不是每个页面各算一套 |
| 稳定高效可运维 | 高峰可用、任务可恢复、问题可定位 | 不是只追求页面打开 |
| 可持续交付与演进 | 组件复用、接口契约、版本可回滚 | 不是一次性交付 |

### 1.3 技术约束

```text
保持新前端
统一组件和页面模板
不把新前端本身当作业务目标
新前端服务于“可持续交付与演进”
```

### 1.4 支撑目标

```text
业务可运营
配置可治理
接口可开放
成本可控制
```

这些目标不单独扩大核心目标数量，但必须体现在设计中。

### 1.5 设计原则

```text
平台能力下沉，场景能力上浮
共享对象统一，场景字段隔离
流程可配置，但不牺牲资金安全
权限后端强制，不依赖前端隐藏
编码展示友好，不显示裸 ID
业务对象有状态、有动作、有日志
页面可复用，不为单页重复造轮子
数据有来源，指标有口径
关键动作可审计，异常可定位
```

### 1.6 目标—设计—验收映射

| 核心目标 | 对应设计 | 验收证据 |
|---|---|---|
| 多场景可扩展 | 第 2、3 章：平台层/场景层、场景扩展点、共享对象 | 新场景不复制平台核心；共享能力复用 |
| 业务闭环 | 第 3、6、10、11 章：状态机、审批、详情页、标准页面 | 每个对象有详情、状态和下一步动作 |
| 操作简单好用 | 第 10 章：页面模板、选择器、草稿、批量 | 选择可搜索、可层级、可恢复、可批量 |
| 显示全面可读 | 第 10 章：列表/详情/字段/编码展示 | 无裸 ID、无英文枚举、关键字段完整 |
| 安全合规可审计 | 第 4、12 章：租户、数据范围、字段权限、审计 | 越权被拒绝、导出受控、关键操作有日志 |
| 数据准确一致 | 第 3、5、7 章：主数据、编码、财务口径 | 账单收款对账一致、指标口径统一 |
| 稳定高效可运维 | 第 12 章：异步、监控、备份、恢复 | 批量可重试、问题可定位、备份可恢复 |
| 可持续交付与演进 | 第 10、12、13 章：设计系统、组件、测试、版本 | 新页面复用模板；发布可回滚；契约稳定 |

### 1.7 目标优先级

发生冲突时按以下顺序决策：

```text
1. 安全合规
2. 数据准确
3. 业务闭环
4. 稳定可用
5. 操作体验
6. 扩展效率
```

原则：

```text
不能为了页面好看牺牲权限
不能为了上线速度牺牲资金口径
不能为了单场景需求破坏平台边界
```

## 4. 多租户与权限

### 4.1 权限模型

```text
RBAC + 数据范围 + 字段权限
```

### 4.2 数据范围

```text
PLATFORM      平台级，仅平台管理员，跨租户分次查询
TENANT        本租户
ORG_TREE      本级组织 + 下级组织 + 下级项目
PROJECT       当前项目
PROJECT_SET   指定项目集合
SELF          本人
CUSTOM        自定义
```

### 4.3 财务权限

```text
财务默认范围：ORG_TREE
范围 = 本级组织 + 下级组织 + 下级组织所属项目
```

规则：

```text
不默认看全租户
不默认看平级组织
不默认看上级组织
财务挂租户根组织 → 可看全租户，但必须有显式授权
根组织财务授权需审批和审计
授权有有效期，到期自动收回
```

### 4.4 项目管理员权限

```text
项目管理员默认只能看本项目
只能看与本项目有关联的人员
不能全局搜索人员
不能查看其他项目人员档案
显式授权后才可跨项目
```

人员可见条件：

```text
人员与当前项目存在关系
或存在人员显式授权
```

### 4.5 字段权限

```text
身份证
手机号
住址
合同金额
银行账号
```

规则：

```text
字段权限取交集
显式拒绝优先
默认拒绝
导出同样受控
```

### 4.6 强制范围

以下全部执行数据范围过滤：

```text
列表
详情
导出
搜索
选择器
报表
驾驶舱
审批
```

不能只在前端过滤，后端必须校验。

## 5. 主数据与编码

### 5.1 编码原则

```text
内部 ID 与业务编码分离
内部 ID 用雪花 ID
业务编码用于展示、检索、打印
业务编码不可变
作废不复用
序列按租户/项目/期间独立
并发安全
```

### 5.2 编码规则

| 对象 | 编码规则 | 含年月 |
|---|---|---|
| 项目 | `PRJ-{地区码}-{4位序号}` | 否 |
| 空间 | `SP-{项目编码}-{6位序号}` | 否 |
| 房源 | `HS-{项目编码}-{6位序号}` | 否 |
| 合同 | `HT-{项目编码}-{YYYYMM}-{4位序号}` | 是 |
| 账单 | `BL-{项目编码}-{YYYYMM}-{5位序号}` | 是 |
| 收款 | `PY-{项目编码}-{YYYYMM}-{5位序号}` | 是 |
| 收据 | `RC-{项目编码}-{YYYYMM}-{5位序号}` | 是 |
| 设备 | `DV-{项目编码}-{类型}-{5位序号}` | 否 |
| 工单 | `WO-{项目编码}-{YYYYMM}-{5位序号}` | 是 |
| 审批 | `AP-{YYYYMMDD}-{6位序号}` | 是 |

### 5.3 五级地址

数据源：

```text
https://github.com/657258535/China-Area-Region-Administrative-Divisions
```

更新方式：

```text
平台管理员/运维管理员手动更新
每年至少一次
或行政区划调整公告后更新
不在运行时自动联网
```

更新流程：

```text
下载 province.json 和省份 JSON
→ 导入临时表
→ 校验编码/层级/父子关系
→ 查看变更
→ 发布新版本
→ 记录来源、校验值、操作人
```

### 5.4 地址强制

```text
中文项目 = country=CN 且 locale=zh-CN
中文项目强制省/市/区县/街道/社区五级地址
```

回退：

```text
第五级数据缺失时允许回退
需要 project:region:fallback 权限
不需要审批
必须记录原因和缺失层级
项目标记“地址待完善”
```

### 5.5 编码不可变性

```text
项目编码生成后不因地址修改而重算
已作废编码不复用
已撤销区划不物理删除
历史项目保留旧名称
```

## 6. 审批与流程

### 6.1 审批能力

```text
单级审批
多级审批
顺序审批
平行审批
多人会签 and
多人或签 or
抄送
办理
条件分支
转办
加签
撤回
退回补充
超时提醒
超时自动通过
超时升级
```

### 6.2 模板层级

```text
平台模板
  ↓ PATCH
场景模板
  ↓ PATCH
项目模板
```

默认：

```text
PATCH 继承
允许 NONE
```

### 6.3 PATCH 规则

允许：

```text
增加节点
修改节点名称
修改审批人
修改审批模式
增加条件
增加抄送
```

禁止：

```text
删除平台强制节点
降低平台强制审批要求
绕过金额审批
```

### 6.4 模板解析

```text
项目模板 → 场景模板 → 平台模板
```

同层级按条件匹配：

```text
业务类型
金额
合同类型
项目类型
组织范围
```

### 6.5 模板版本

```text
模板发布后版本不可改
审批实例固定使用发起时版本
上级更新不自动影响下级
下级提示“可升级”
升级需重新发布
```

### 6.6 合同类审批

合同类：

```text
签订
续签
变更
租金变更
期限变更
换房
退租
终止
```

规则：

```text
绑定模板 → 走审批
未绑定模板 → 可直接生效
```

无模板直通限制：

```text
仅授权角色可操作
普通经办人不能直接生效
必须有操作日志
日志类型：CONTRACT_*_WITHOUT_APPROVAL
合同详情时间线显示“无审批直接生效”
```

### 6.7 金额类审批

必须审批：

```text
账单调整
账单减免
退款
收款冲正
押金退还
补贴抵扣
发票红冲
```

规则：

```text
无模板也强制审批
正常收款不审批
```

默认阈值：

```text
< 100        项目负责人
100–5000     项目负责人 + 场景财务
≥ 5000       项目负责人 + 场景财务 + 平台财务
```

阈值可配置：

```text
平台默认
场景可覆盖
项目可在允许范围覆盖
版本化
生效时间
```

### 6.8 审批状态与业务状态

```text
业务状态：草稿/生效/变更中/退租中/已终止
审批状态：未提交/审批中/已通过/已驳回/已撤回
```

两者分离，不能混用。

## 7. 财务与账务

### 7.1 金额字段

```text
账单金额 amount
补贴金额 subsidy_amount
减免金额 waiver_amount
调整金额 adjustment_amount
应付金额 payable_amount
已核销金额 paid_amount
未收金额 outstanding_amount
期初金额 opening_amount
```

### 7.2 公式

```text
应付 = 账单金额 - 补贴 - 减免 - 调整
欠费 = 应付 - 已核销
当期收缴率 = 当期实收 / 当期应收
总欠费 = 期初欠费 + 当期欠费
期初欠费回收率 = 期初回收 / 期初欠费
```

```text
对账
```


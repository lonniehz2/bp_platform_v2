# 菜单编码统一方案

> 状态：方案稿，未编码  
> 目标：解决角色页“场景菜单”和左侧栏菜单不一致  
> 原则：页面级权限，分组只做展示

---

## 1. 当前问题

系统存在两套菜单：

### 左侧栏

来源：`navConfig.js`

```text
9 个分组
48 个导航项
```

### 角色页

来源：`bp_menu`

```text
27 个菜单节点
```

结果：

```text
角色页能授权的菜单 ≠ 左侧栏实际显示的菜单
角色页出现“场景菜单”，但左侧栏没有对应项
部分页面无法精确授权
```

---

## 2. 统一目标

```text
一份菜单主数据
一套菜单编码
左侧栏和角色页共用
页面级授权
```

菜单编码规则：

```text
menu_code = 页面唯一编码
parent_code = 所属分组
route = 页面路由
menu_name = 中文名称
sort_no = 排序
```

## 4. 旧菜单码迁移映射

旧 `bp_menu` 的 27 个编码需要迁移到页面编码。

| 旧编码 | 新页面编码 |
|---|---|
| dashboard | dashboard |
| search | search |
| message | message |
| asset | asset、listings、houses、spaces、calendar、shortrent |
| person | person、keyring |
| application | applications、allocations、qualification |
| waitlist | waitlist |
| contract | contracts、contractChanges、exchanges、terminations |
| billing | billing、deposits、subsidies、cashflow、fee、arrears |
| audit | audit |
| service | workOrders |
| device | devices、deviceBind、grants、houseAccess |
| access | accessRecords |
| complaint | complaints、appeals、visits |
| publicity | publicities |
| alert | alertCenter、patrol、devEvents |
| credit | credit |
| shortrent | shortrent |
| system | sys、rbac、batchImport、reports、orgs |
| gov | gov |
| calendar | calendar |
| energy | energy |
| help | help |
| config | rbac、batchImport、sys |
| open | 暂停使用，映射到 sys |

说明：

```text
旧角色如果被授予“asset”
迁移后应拥有 asset、listings、houses、spaces、calendar、shortrent

旧角色如果被授予“billing”
迁移后应拥有 billing、deposits、subsidies、cashflow、fee、arrears
```

这需要业务确认，因为会扩大旧角色的可见页面。

## 5. 数据模型

```text
bp_menu
  id
  scene_code
  menu_code
  parent_code
  menu_name
  menu_type
  route
  sort_no
  menu_status
```

建议增加：

```text
permission_code   页面/动作权限编码
menu_level        GROUP / PAGE / ACTION
```

分组节点：

```text
menu_code = group_workbench
menu_type = GROUP
route = null
```

页面节点：

```text
menu_code = dashboard
parent_code = group_workbench
menu_type = PAGE
route = /guarantee/dashboard
```

## 6. 左侧栏改造

当前：

```text
navConfig.js 写死分组和菜单
allowedMenus 过滤
```

改造后：

```text
GET /menus 返回当前用户菜单树
左侧栏直接渲染
navConfig 只保留图标/分组兜底
```

如果短期不改左侧栏：

```text
navConfig 的 menu 字段必须使用新页面编码
不能再使用父级编码
```

---

## 7. 角色页改造

角色详情：

```text
基本信息
功能权限
  ├── 菜单权限
  └── 动作权限
数据范围
成员
```

不再显示独立的“场景菜单”。

菜单权限树直接使用统一后的菜单树：

```text
收费与账务
  ├── 账单
  ├── 押金
  ├── 补贴
  └── 收款记录
```

## 8. 迁移步骤

### 第一步：生成菜单清单

```text
从 navConfig 导出 48 个页面
生成 menu_code / parent_code / route / name / sort
```

### 第二步：补充 bp_menu

```text
新增 9 个分组节点
新增 48 个页面节点
旧 27 个节点保留但标记停用
```

### 第三步：迁移角色授权

```text
旧角色菜单 → 新页面菜单
按映射表展开
管理员默认全部页面
财务/客服等角色按原范围映射
```

### 第四步：左侧栏切换

```text
菜单从后端返回
navConfig 不再作为权限源
```

### 第五步：角色页切换

```text
权限树使用统一菜单
删除“场景菜单”
```

### 第六步：回归

```text
admin
finance
auditor
asset clerk
```

---

## 9. 风险

```text
旧角色授权迁移会扩大或缩小范围
旧菜单 ID 仍被历史数据引用
前端 navConfig 与后端菜单短期并存
角色页和左侧栏切换不同步
```

控制：

```text
迁移前备份
先只读对比
先影子菜单
再切换
保留回滚
```

---

## 10. 需要确认

```text
1. 是否采用“页面级权限”？
2. 旧父级菜单授权是否按映射表展开到子页面？
3. 旧菜单节点保留停用，还是删除？
4. 左侧栏是否改为后端菜单驱动？
5. 角色页是否删除“场景菜单”，只保留功能权限树？
```

建议全部为“是”。

---

## 11. 结论

```text
先统一菜单编码
再改左侧栏
再改角色页
最后加数据范围
```

不要在菜单编码未统一前继续补角色页功能，否则还会返工。

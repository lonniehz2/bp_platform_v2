# 多场景空间资产运营平台框架设计

> 阶段：Phase 0 框架设计  
> 第一场景：保障房  
> 第二场景：物业 V1  
> 目标：平台提供框架，场景提供策略

---

## 1. 设计原则

```text
平台不依赖场景表
场景可以依赖平台
场景通过 scene_code / biz_type / policy 扩展
平台能力可渐进落地
老系统不改核心，只做适配
```

禁止：

```text
平台表出现 guarantee_*/prop_* 外键
平台接口返回场景专属字段
用 if (scene == ...) 写平台核心逻辑
把所有表都改成 bp_ 前缀
```

## 16. 待确认问题

```text
1. 场景包由平台预置还是租户自建
2. 经营模式是否允许楼栋级覆盖
3. 内房/床位是否允许同时存在
4. 保障房老系统哪些模块先迁移
5. 合同/账单是否本期就接平台内核
6. 设备/授权是否本期接入
7. 菜单组合由平台配置还是场景代码生成
8. 数据迁移的租户/ID 映射规则
```

## 17. 结论

```text
先做平台框架，不做所有场景
保障房先验证，物业第二
平台只提供稳定框架
场景保留业务策略
老系统渐进适配，不整体重写
```

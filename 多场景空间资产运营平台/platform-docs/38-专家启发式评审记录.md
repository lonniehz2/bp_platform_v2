# 专家启发式评审记录

> 类型：设计评审视角的启发式走查  
> 说明：不是外部专家评审，也不是真人可用性测试；用于评审前提前发现问题  
> 依据：Nielsen 10 项启发式 + 五参考页面原型

---

## 1. 评审范围

```text
运营驾驶舱
申请与资格
合同详情
账单收费
设备绑定
```

评审视角：

```text
产品/交互
财务业务
运营/项目管理
```

---

## 2. 评审方法

```text
逐页走查
按 10 项启发式检查
记录问题
判定严重级别
给出修改建议
```

严重级别：

```text
阻塞：无法完成核心任务
高：容易做错或明显困惑
中：需要停顿或试错
低：表达/视觉优化
```

---

## 3. 启发式检查结果

### H1 系统状态可见

发现：

```text
合同状态、账单状态、设备绑定状态清楚
驾驶舱账期切换有提示
但“本期/期初”口径只有一段说明，缺少指标旁的即时解释
```

级别：中

建议：

```text
每个财务指标增加“?”提示
说明统计范围和是否含期初
```

### H2 贴近真实业务语言

发现：

```text
“本期实收”“期初回收率”对财务可理解
“未结清账单”比“未缴”更贴近合同场景
部分页面“未缴/未结清”混用
```

级别：低

建议：

```text
统一账单状态用语
合同详情用“未结清账单”
账单列表用“未缴/部分缴/已缴”
```

### H3 用户控制与自由

发现：

```text
弹窗可关闭
合同收款可取消
设备来源跳转后没有明显“返回 102”
```

级别：中

建议：

```text
来源跳转后提供“返回原空间”
或面包屑保留路径
```

### H4 一致性与标准

发现：

```text
驾驶舱写“本期实收”
账单页写“本期已收”
已修正为“本期实收”
主操作按钮样式基本统一
```

级别：低

建议：

```text
建立财务术语表
页面统一使用
```

### H5 错误预防

发现：

```text
合同收款已做未选择、超额校验
设备解绑、账单退款在原型中只有 toast，没有二次确认
```

级别：高

建议：

```text
解绑、退款、冲正、退租必须二次确认
显示影响范围
```

### H6 识别优于记忆

发现：

```text
合同收款直接展示账单列表，不需要记住账单号
设备继承显示来源路径
驾驶舱指标较多，期初/当期需要记忆区分
```

级别：中

建议：

```text
合同收款保留账单列表
驾驶舱将“本期”和“期初”分组展示
```

### H7 效率

发现：

```text
多账单可逐笔选择
没有“全选未结清”快捷操作
```

级别：低

建议：

```text
增加“全选未结清”或“选择全部”
但默认不全选，避免误收
```

### H8 美观与极简

发现：

```text
驾驶舱 9 个指标卡偏密
本期与期初混在同一行
```

级别：中

建议：

```text
分成“本期经营”和“期初/欠费”两组
或使用分区标题
```

### H9 错误提示与恢复

发现：

```text
原型只有成功 toast
没有加载失败、空数据、无权限的完整展示
```

级别：中

建议：

```text
正式页面必须有加载/空/错误/无权限四态
错误提示给出下一步
```

### H10 帮助与文档

发现：

```text
没有指标说明
没有字段帮助
没有“如何收款/如何解绑”的上下文帮助
```

级别：中

建议：

```text
关键指标加 tooltip
关键动作加简短说明
帮助中心提供流程说明
```

## 5. 必须在评审前处理的

```text
HX-05 解绑/退款二次确认
HX-03 来源跳转返回
HX-01 财务指标口径提示
HX-09 空/错/无权限状态
```

其余可作为实现阶段优化。

## 6. 评审结论

```text
五个页面主流程可理解
合同收款和设备继承的交互方向成立
财务术语需要少量统一
危险动作确认和状态页需要补齐
```

本记录是设计视角预评审，不等同于外部专家评审或真人测试。

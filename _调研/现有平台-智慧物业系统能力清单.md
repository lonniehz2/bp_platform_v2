## 1. 现有智慧物业系统 17 个子系统（原文照录）

| # | 子系统 | 原文要点 |
|---|---|---|
| 1 | **智慧门禁系统** | ① 大门门禁、单元门禁、电梯控制**自动联动**<br>② **门禁授权是对人进行授权**，授权人可用自己实名过的手机（APP/小程序/NFC）、身份证、人脸、指纹、随身码等开门呼梯（人脸、指纹需所幢设备支持）<br>③ 老人孩子可由业主（监护人）申领手环/NFC 卡贴/门禁卡，丢失可自行在手机挂失<br>④ **所有授权都是针对人和其所住位置关联的**——授权 A 出入（A 入住 1 幢 2 单元 501），A 就自动获得大门、1 幢 2 单元单元门、所在单元电梯到达 5 层的权利<br>⑤ 所有开门呼梯方法和介质都是用户自己具有的介质<br>⑥ **人员授权都是业主自主完成**（家人、租客、同住人、家政保姆、亲朋好友、访客外卖等）<br>⑦ 门禁服务属**基础服务**类别 |
| 2 | **智慧访客系统** | ① 访客由小区内部居住人员邀请进入，居住人通过手机或访客码生成器生成**随机访客码**，访客凭同一访客码在授权时间范围内**单次**进出大门、单元和梯控，到达邀请人所在楼层<br>② 访客只能单次进出所要去的位置，**无权限进出其它单元或楼层**<br>③ 驾车访客车牌可由邀请者填入；邀请者名下有空余车位则可直接进入停放，否则按社会车辆规则执行<br>④ 访客服务属**增值服务**类别 |
| 3 | **智慧梯控系统** | ① 每个居住人员的梯控授权**和其门禁授权联动**<br>② 可**分层控制**，自由设定部分楼层需梯控、部分楼层不梯控<br>③ 呼梯方法除常规开门方式外，还可增加**扫码呼梯**（便于拥挤场景）<br>④ 梯控服务属**增值服务**类别 |
| 4 | **智慧停车管理系统** | ① 用户可自由设定停放自己车位的车辆车牌，**数量和时间可住户自己设定**<br>② 自己车位用完，其余车辆无法按免费车辆进入<br>③ **整个停车系统管理是和人关联的**，每个业主进入车辆数量不得大于其可停车数量<br>④ 支持临时车辆各种计费规则<br>⑤ 支持**扫码支付**，支持预先支付或车闸前支付<br>⑥ 支持**车位临时转借**<br>⑦ 支持**车位分时共享**（空余时间对外共享增加创收） |
| 5 | **电瓶车安全充电系统** | ① 小区公共位置安装电瓶车安全充电设备<br>② 设备具有过压、过流、短路、漏电等保护<br>③ 支持**按时计费和按电量计费**<br>④ 用户可通过手机微信直接充电支付 |
| 6 | **人脸抓拍及溯源系统** | ① 公共门禁、重要公共位置安装人脸抓拍摄像机<br>② 可对**尾随而入**的人群留下人脸记录，便于溯源<br>③ 提供**以图搜图**功能，实现访客轨迹溯源<br>④ **陌生人脸实时告警**，值班室即时发现陌生人员 |
| 7 | **智能巡更系统** | ① 每个保安配备保安终端，上班需**刷脸登录**自己账号<br>② 规定巡更任务时间内完成巡更，系统自动记录每个保安每次巡更的**线路时间点**<br>③ 巡更点安装门禁/梯控/车闸/门锁等设备处，保安终端**自动感应**；其余地方用终端读取电子标签<br>④ 巡更中发现问题可用拍照、文字提交<br>⑤ 管理后台可**动态显示所有巡更任务完成情况**，便于考核<br>⑥ 保安终端支持**对讲、巡更、一键求助接收处置** |
| 8 | **智能保洁管理系统** | ① 保洁任务分**卫生检查**和**清洁打扫**<br>② 保洁人员须在支持 NFC 的手机上安装保洁模块 APP，在每个卫生检查点用手机读取电子标签<br>③ 需打扫处**拍照上传打扫前后图片**<br>④ 按实际工作量计酬 |
| 9 | **一键求助系统** | ① 在门禁、梯控、车闸、公共安全隐患位置、孤寡老人特殊群体家里安装一键求助按钮<br>② 保安终端和值班中心**声光终端即时告警**并即时处置<br>③ 按钮采用**电池供电**，方便安装或携带 |
| 10 | **线上缴费系统** | ① 各类缴费可在手机自助完成（**微信、支付宝**等）<br>② 支持**物业费、车位管理费、垃圾清运费、能耗费、包月停车费**等收费类别<br>③ **缴费和各类控制系统的授权权限自动关联** |
| 11 | **第三方服务管理系统** | ① 设置管理各类第三方服务供应商（水电维修、绿化养护、卫生保洁、电梯运维、设施维修、快递寄送等）<br>② 物业审核各类供应商，签约后分配后台账号，供应商可**自行授权其服务人员按单上门服务**，并**自动获得相应门禁、梯控授权**<br>③ 服务供应商可在用户报修后**抢单接单**，安排授权自己的服务人员上门 |
| 12 | **自助服务系统** | ① 物业值班中心配置 **24 小时自助服务终端**<br>② 不会用智能手机的人员可到自助终端办理**授权、缴费、报修**，值班人员协助操作 |
| 13 | **投诉建议** | ① 用户通过手机小程序提交投诉建议并上传图片<br>② 处理进展和结果**实时查看**<br>③ 监督物业处理进度，提升满意度 |
| 14 | **报修管理** | ① 住户或工作人员可在手机上传各类报修<br>② 相应工作人员和对应第三方服务供应商**都会接到报修事件**<br>③ 维修进展**实时跟踪查询** |
| 15 | **小区投票系统** | ① 物业或业委会在后台设置投票事项标题和内容（单项或多项）<br>② 用户手机完成投票提交<br>③ 重要投票可**设定刷脸确认**，确认是否本人投票<br>④ 投票结果后台实时查询 |
| 16 | **小区公告** | 提供各类小区公约、通知、宣传等内容 |
| 17 | **云小店系统** | ① 整合业主和周边服务资源<br>② 住户或周边供应商可提供各类服务和产品<br>③ 物业负责规范性和合法性管理审核 |

**备注（原文）**：用户可以自己定义增值服务类别，比如梯控、访客邀请、临时车辆添加等功能；**对于拖欠物业费、车位管理费等，可以按照设定自动关闭对应用户的增值服务功能**。

## 2. 现有系统的标准实施路径（原文）

```
① 申请注册 ──► ② 资产初始化 ──► ③ 设备初始化 ──► ④ 基础设置 ──► ⑤ 通知业主 ──► ⑥ 日常管理
联系云门道       创建资产信息        安装设备         设置收费策略      通知业主       审核
或在网页申请     或联系导入          绑定设备         是否实名          登录小程序     业主管理
由云门道创建     资产信息            在设备管理中     添加工作人员账号   添加人员       车辆管理
账号                                 选取设备选择                       业主认证       巡更管理
                                     资产位置                                         报警管理
                                                                                     第三方服务商管理
```

**关键事实**：
- 资产结构由客户**在「资产管理」中自行创建**（如苑、幢、单元等），再**把具体资产信息表格导入** → 说明现有系统**已有空间层级 + 批量导入**能力
- 设备绑定方式：**在「设备管理」中选取设备 → 选择设备安装的资产位置** → 说明**已有设备-空间绑定关系**
- 权限管理：创建用户、设置权限 → 说明**已有 RBAC**
- 业主认证不通过需**人工审核**（审核管理 → 认证记录 → 通过/驳回）
- 系统**有「是否实名」开关设置** → 与门锁的"实名工作模式"对应
- 设备清单：智能门禁、人脸识别机、智能车闸、梯控、充电桩、一键报警、水表、电表等
- 有**自助台**，可协助业主注册并实名认证（需携带身份证）

## 3. 对业务平台设计的影响

### 3.1 可复用 / 已被现有物业系统覆盖，业务平台需谨慎处理

| 能力 | 现有物业系统 | 业务平台处理建议 |
|---|---|---|
| 空间层级（苑/幢/单元） | ✅ 已有（资产管理 + 表格导入） | **需评估**：是复用物业系统的资产模型，还是业务平台自建？**存在重复建设风险，待决策** |
| 设备-空间绑定 | ✅ 已有 | 同上，需决策 |
| 人员授权（业主自主） | ✅ 已有 | 已有能力与 IoT §8 人员授权重叠，业务平台应复用而非重造 |
| 门禁/梯控/车闸联动 | ✅ 已有 | 业务平台不重复实现设备联动 |
| 访客码（单次/时间范围） | ✅ 已有 | 业务平台只需业务规则层 |
| 线上缴费（微信/支付宝） | ✅ 已有（物业费/车位费/能耗费等） | **重要**：说明**支付通道与账务能力已有**，业务平台可复用而非从零对接 |
| **欠费自动关停增值服务** | ✅ 已有（按设定自动关闭） | 与"欠费关停权限"同源，业务平台应复用该机制并按保障房政策扩展 |
| 报修管理 | ✅ 已有 | 业务平台工单域可复用/扩展 |
| 投诉建议 | ✅ 已有 | 可作为业务平台投诉模块的基础 |
| 智能巡更 | ✅ 已有（含终端、电子标签、刷脸登录） | 业务平台巡更可复用 |
| 智能保洁 | ✅ 已有（NFC 打卡、前后照片） | 同上 |
| 第三方服务商管理（含授权） | ✅ 已有 | 与工单/维保域重叠，需统一 |
| 人脸抓拍溯源（以图搜图、陌生人告警） | ✅ 已有 | **重要**：说明**告警与视频类能力比预想强**，业务平台告警中心可对接 |
| 一键求助 | ✅ 已有 | 可纳入业务平台告警域 |
| 电瓶车充电计费 | ✅ 已有 | 二/三期考虑 |
| 车位管理（转借、分时共享、临停计费） | ✅ 已有 | 停车管理可复用 |
| 小区投票（含刷脸确认） | ✅ 已有 | 保障房场景可扩展为"配租意向确认"等 |
| 小区公告 | ✅ 已有 | 业务平台消息中心可复用 |
| 云小店 | ✅ 已有 | 与业务平台无关 |
| RBAC 权限管理 | ✅ 已有 | 业务平台组织权限需**兼容或重构**，待决策 |
| 是否实名开关 | ✅ 已有 | 与"实名工作模式"对应 |

### 3.2 ⚠️ 关键决策点（本调研最重要的产出）

**现有「智慧物业系统」与拟建的「业务平台」存在大面积能力重叠**，尤其是：
空间资产、设备绑定、人员授权、缴费账务、报修工单、巡更保洁、告警、公告。

→ **必须在第二轮架构设计前明确以下战略问题**：

| # | 决策问题 | 选项 |
|---|---|---|
| A | 业务平台与现有智慧物业系统是什么关系？ | ① 业务平台**取代**物业系统（迁移整合）<br>② 业务平台**并列**独立（两套并存，接口互通）<br>③ 业务平台作为**内核**，物业系统作为其上的一类场景前端 |
| B | 空间资产模型由谁主控？ | ① 业务平台主控，物业系统改为消费方<br>② 物业系统主控，业务平台同步<br>③ 双写/双向同步 |
| C | 账务与支付通道复用还是自建？ | ① 复用现有支付与账务<br>② 业务平台自建账务，仅复用支付通道<br>③ 完全自建 |
| D | 现有物业客户如何平滑过渡？ | 涉及存量数据迁移、双跑期、切换方案 |

> **建议**：选 **A③ + B① + C②**，即业务平台作为统一内核（空间、人员、权益、账务主控），物业系统收敛为"物业场景前端"，避免长期双主数据。

### 3.3 现有物业系统**未覆盖**（业务平台必须新建）

| 缺口 | 说明 |
|---|---|
| 保障房资格审核全流程 | 物业系统面向市场化业主，无准入审核 |
| 轮候 / 摇号 / 选房 / 配租 | 无 |
| 保障房政策合同（含补贴） | 无 |
| 政策租金与补贴发放、财政对接 | 物业系统只有市场化收费 |
| 年度复核 / 资格年审 / 退出管理 | 无 |
| 与住建/公租房管理信息系统对接 | 无（只有公安接口，见小程序"云门道云租客"） |
| 监管类报表与政务报送 | 无 |
| 数据大屏（政务监管口径） | 物业侧未见政务大屏 |
| 多租户（区县级隔离） | 未见 |

## 4. 存疑点

| # | 存疑点 | 需核实 |
|---|---|---|
| 1 | 「智慧物业系统」与「云门道智慧云」是否为同一套系统的不同品牌称谓？ | 需确认产品线关系 |
| 2 | 简介中的 17 个子系统是否**均已上线**，还是部分为规划/宣传？ | 需索取实际菜单或演示 |
| 3 | 「缴费和各类控制系统的授权权限自动关联」「拖欠自动关闭增值服务」的具体配置粒度与实现方式 | 直接影响业务平台欠费关停设计 |
| 4 | 空间资产模型的数据结构（层级、编码规则、字段） | 直接影响业务平台空间模型设计 |
| 5 | 现有账务/支付通道是否可被业务平台调用（是否有 API） | 影响第二轮架构 |
| 6 | 人脸抓拍溯源系统的技术来源（自研/第三方）与接口能力 | 影响告警与视频联动设计 |
| 7 | 第三人服务商的"自动获得门禁梯控授权"如何实现（是否走 IoT 人员授权） | 影响授权编排统一性 |

## 2. 部署形态（三档）—— **可直接借鉴的分档策略**

| 档位 | 厂商描述（原文要点） | 适用 |
|---|---|---|
| **公有云（标准版）** | 基于系统标准化模式，业务快速接入；适合**千间以内**公寓管理方案 | 中小客户 |
| **私有云** | 基于局部定制模式，按客户需求定制功能，部署在**寓盟 SaaS 集合私有云库**中，实时监控 | 中型客户 |
| **私有化** | 基于**更大范围的模块个性化定制**需求，私有化部署至**甲方指定云服务器**，定期提供系统更新维护与行业最新功能数据同步 | 政府/国企/大型 |

**⭐ 可借鉴点**：三档的**划分依据是"定制深度 + 数据主权"**，而非单纯的规模。
我们的设计文档只写了"SaaS + 私有化双模"，**建议细化为三档**，并明确每档的**功能边界、定制范围、升级与维护责任**。
特别是"私有云"这一中间档——它在政务项目里非常实用（数据不出域但享受厂商持续升级）。

### 3.1 与我们功能清单的对照

| 竞品模块 | 我们是否覆盖 | 说明 |
|---|---|---|
| 线索管理 | ❌ **未覆盖** | 我们**没有"线索/商机"概念**。对**市场化的公寓/出租房场景**是刚需（获客→跟进→转化）。**建议纳入场景包** |
| 房源管理 | ✅ 覆盖（§4.3 空间资产管理） | 一致 |
| 财务管理 | ✅ 覆盖（§4.9 计费与账务） | 一致，但**我们的保障房场景更强调政策租金与补贴** |
| 合约管理 | ✅ 覆盖（§4.8 合同管理） | 一致；竞品对接**契约锁/E签宝**，我们**尚未确定电子签章供应商**（待确认事项 §10-B15） |
| 客户管理 | ⚠️ 部分覆盖（§4.4 对象档案） | 竞品强调**会员体系/标签/优惠券/黑名单**，偏**营销与客户运营**；我们的"对象档案"偏**资格与合规**。两者**定位不同**，可互补 |
| **短租管理** | ⏳ 未覆盖（酒店民宿场景，二期） | 竞品有独立模块，印证**长租/短租需分开建模**（价格日历、订单、按夜计费） |
| **多经管理** | ❌ **未覆盖** | **"多种经营"**：广告位、增值服务、商铺、公共空间经营等。**这是我们完全遗漏的业务域**，对物业/园区/公寓场景都可产生收入 |
| 巡房管理 | ⚠️ 部分覆盖（§4.15 工单与维保 + 巡更） | 竞品的"巡房"是**房源状态例行检查**，与我们理解的"智慧巡更（保安打点）"不同。**这是保障房"入户走访"的数字化替代**，值得单列 |
| 资产管理 | ✅ 覆盖（§4.3） | 一致 |
| 租后服务 | ✅ 覆盖（§4.15 工单与维保） | 竞品的**四端联动**（运营后台/客户端/门店端/售后端）+ 全生命周期（发起→派单→处理→验收→评价→结单）与我们设计一致 |
| 数据中心 | ✅ 覆盖（§4.17 报表 + §4.18 大屏） | 竞品有 **17 种报表** + 数据大屏 |
| **备案管理** | ❌ **菜单中没有，我们设计中也未单列** | ⭐ **重要**：竞品支持**"房源、合同、财务"自动同步到房管局备案**。这与漳州标【指标14】"与公租房管理信息系统对接"**高度相似**，建议我们**单列"监管报送/备案"域** |
| 智能设备 | ✅ 覆盖（§4.12） | 竞品强调**房租解锁、合同打通**（与我们的合同联动权限一致） |
| **审批管理** | ⚠️ 我们列为"需新建"（§1.1B 丙类） | ⭐ **竞品有"自定义审批流程"独立模块** → **印证审批流引擎是必备能力**，且应是**独立模块**而非散落的审核按钮 |

| 员工管理 | ✅ 覆盖（§4.2 组织与权限） | 一致 |
| 配置中心 | ✅ 覆盖（§4.19 系统管理） | 一致 |

## 4. 场景解决方案（9 类）

| # | 场景 | 厂商描述 | 与我们场景包的对应 |
|---|---|---|---|
| 1 | 长租公寓 | 高效管理，稳定租赁 | 智慧公寓 |
| 2 | 服务式公寓 | 全方位服务，高效运营 | 智慧公寓（高端） |
| 3 | 短租民宿 | 灵活运营，收益最大化 | 酒店/民宿 |
| 4 | **企业宿舍** | 高效管理，降低成本 | **智慧宿舍** |
| 5 | 企业园区 | 高效管理，优化资源 | 智慧物业（园区） |
| 6 | **政府保租房** | 规范管理，保障住户 | **保障房（保租房）** |
| 7 | **政府公租房** | 优化管理，提高满意度 | **保障房（公租房）—— 我们的首期** |
| 8 | **人才公寓** | 专业管理，吸引人才 | **保障房（人才公寓）** |
| 9 | 学生宿舍 | 高效管理，提升居住质量 | 智慧宿舍（校园） |

**⭐ 关键校准确认**：竞品把**保障房拆成"保租房 / 公租房 / 人才公寓"三个独立场景**。
而我们的设计文档把"保障房"作为一个场景。**建议修正**：
- 保障房政策在**保租房（保障性租赁住房）**、**公租房**、**人才公寓**三者间**准入条件、租金标准、补贴方式、退出规则差异很大**；
- 三者应作为**同一"保障房场景包"下的三个子策略**（共用资格审核→配租→合同→租金→退出主流程，差异在**规则配置**）。

## 5. 公租房 / 保租房专题（最关键）

### 5.1 厂商自述的「业务挑战」（官网原文要点）

| 挑战 | 厂商原文要点 |
|---|---|
| **监管机制不够透明** | 保障房的**申请、分配和管理过程透明度不足**，导致公众信任度下降，滋生潜在腐败问题 |
| **资源分配不公** | 一些不法分子通过**伪造材料**获取保障房，破坏资源的公平分配 |

> 后续"解决方案"部分在抓取时被站点导航截断，未能取得完整正文。
> 建议后续通过**商务沟通索取**其公租房方案 PPT/白皮书。

### 5.2 厂商自述的保租房专属功能（来自行业软文，原文）

> "寓盟管家支持**房源信息上报、租金定价管控、租户资格审核**等保租房专属功能，
> 提供完整的**财务对账与报表体系**，满足**政府监管与内部管理双重需求**。"

**⭐ 这三个词直接印证我们的设计判断**：
1. **房源信息上报** → 对应"监管报送/备案"域（我们未单列）
2. **租金定价管控** → 对应我们的"政策租金"（我们已覆盖，但竞品强调**"管控"**即**政府侧审批与限价**，值得强调）
3. **租户资格审核** → 对应我们的"资格审核"（§4.6，我们已覆盖）

### 5.3 人才公寓场景要点（原文）

- 面向**高学历、高素质人才群体**，对服务品质有更高期待；
- **租客端小程序**：在线报修、费用查询、合同签署；
- **运营端**：智能提醒、工单管理、服务评价 → 实现服务流程的**标准化与可追溯**。

### 5.4 企业员工宿舍场景要点（原文）

- 通常涉及**多楼栋、多房型、多企业**的复杂管理场景；
- 支持**批量导入房源、批量办理入住、集中费用结算**；
- ⭐ 支持与**企业 HR 系统对接**，实现**员工信息同步与权限联动**。

**⭐ 可借鉴点**：**"与企业 HR 系统对接"** 是我们完全没想到的集成方向。
对宿舍/园区场景，员工入职离职驱动门禁权限是刚需（入职自动授权、离职自动回收）。

## 6. 值得借鉴的设计思路（提炼）

> 按"对我们当前设计的价值"排序。

| # | 借鉴点 | 竞品做法（原文依据） | 对我们的建议 |
|---|---|---|---|
| **1** | **审批流引擎必须是独立模块** | 独立"审批管理"模块 + "自定义审批流程（易配置、易管理、易操作）" | ✅ **强印证**：我们已判定"无审批流引擎"是缺口。应作为**内核级独立模块**（流程设计器 + 节点 + 条件分支 + 会签），而非散落的审核按钮 |
| **2** | **监管报送/备案应单列业务域** | "系统自动将**房源、合同、财务**同步到房管局备案" | ✅ **新增**：我们设计中没有"备案/监管报送"域。建议**单列**，覆盖：房管局备案、公租房管理信息系统对接、公安可信身份平台、住建报送 |
| **3** | **多组织 + 多账套 + 近千种权限** | "支持**多主体、多架构、多账套**"；"可自定义多层级组织架构，自定义各种角色。**细分近千种权限**" | ⚠️ **强化**：我们只写到"RBAC + 数据权限"。应明确 **多账套（财务主体隔离）** 与 **权限颗粒度目标**（菜单/按钮/数据/字段） |
| **4** | **部署分三档而非两档** | 公有云（千间以内）/ 私有云（局部定制）/ 私有化（甲方云服务器） | ✅ **细化**：把我们的"SaaS + 私有化双模"改为三档，并明确各档定制边界与升级责任 |
| **5** | **合同全生命周期 + 明确电子签章供应商** | "从合同**发起、审批、签订、执行、归档、统计**全生命周期"；对接**契约锁、E签宝** | ✅ **补强**：我们已列"待确认电子签章供应商"，竞品已明确选型 → **建议直接评估契约锁/E签宝** |
| **6** | **"合同签错、退错支持一键还原"** | 原文："合同签错、退错、支持**一键还原**" | ⭐ **新增功能点**：合同操作可回滚。政务场景容错很重要 |
| **7** | **多经管理（多种经营）** | 独立"多经管理"模块，定位"多元业务，一体管理" | ⭐ **新增业务域**：广告位、增值服务、商铺、公共空间经营收入。**对物业/园区/公寓场景是收入来源** |
| **8** | **巡房管理 ≠ 巡更** | "巡房管理：房源状态，实时监控" | ⭐ **概念澄清**：我们的"智慧巡更"是保安打点；竞品的"巡房"是**房源状态例行检查**。对保障房，这正是**"入户走访/使用情况核查"的数字化替代**（漳州标【指标19】②要求"替代人工入户走访，减少走访频次"）→ **应单列"巡房/走访"模块** |
| **9** | **与企业 HR 系统对接** | "支持与企业 HR 系统对接，实现员工信息同步与权限联动" | ⭐ **新增集成方向**：宿舍/园区场景，**入职自动授权、离职自动回收** |
| **10** | **单设备登录限制、安全登录模式** | 2026 年 3 月版本升级："支持安全登录模式灵活配置、**单设备登录限制**" | ⭐ **新增安全能力**：与厂家方案中"手机唯一性绑定"呼应 |
| **11** | **财务对账的细粒度能力** | "支持**自定义添加账单**及业务数据自动生成账单"；"支持每笔收支的**审核**"；"来源或去向不明的款项录入系统，查证后**关联到对应的应收账目**"；"支持业务数据变更及**数据库变更的账务数据校验**" | ⭐ **强化账务域**：特别是**"未知款项挂账后关联应收"**（资金对账刚需）与**"账务数据校验"**（数据一致性） |
| **12** | **租后服务四端联动 + 全生命周期** | "运营后台、客户端、门店端、售后端**四端联动**"；"发起 → 派单 → 处理 → 验收 → 评价 → 结单" | ✅ 印证我们的工单设计，建议**明确四端职责** |
| **13** | **IOT 与业务深度打通** | "房**租金解锁**，合同打通，实现租客与系统的实时交互" | ✅ **强印证**我们的"合同联动权限""欠费关停"设计方向 |
| **14** | **线索/营销（仅公寓场景需要）** | 线索管理、营销中心（邀请有礼、拼团、砍价、多渠道分发到闲鱼/贝壳/58 等） | ⚠️ **归入场景包**：保障房不需要，但**公寓/出租房需要** → 印证"场景包"架构必要性 |
| **15** | **会员体系与黑名单** | "针对不同会员植入优惠券，降低流失"；"有不良或违规行为的租客，支持**拉入黑名单**" | ⭐ **部分借鉴**：保障房可对应"**失信名单/违规对象名单**"（漳州标"转租转借"处置需要） |
| **16** | **敏感数据加密 + 操作日志全程留痕** | "权限精细化管控、**操作日志全程留痕**、**敏感数据加密存储**" | ✅ 印证我们的"全链路留痕"原则 |
| **17** | **配置中心独立** | 独立"配置中心"模块 | ✅ 印证 §4.19 系统管理设计 |
| **18** | **短租独立建模** | 独立"短租管理"模块 | ✅ 印证"长租/短租分开建模" |
| **19** | **资产负债分离（房源/资产分离）** | "房源管理"与"资产管理"是两个模块；"支持**小区、整栋、楼层、房间、床位**多房态管理" | ⭐ **重要**：**"床位"这一层级**是我们的空间树（片区→楼栋→单元→楼层→房间）**没有的**。宿舍场景必需（一张床一个授权）→ **空间树需支持"床位"层级** |
| **20** | **集团化组织架构两种模式** | "多组织管理架构模式及**集中式门店组织架构模式**灵活配置" | ⭐ **借鉴**：我们应支持"**集团-项目-门店/楼栋**"两种组织形态切换 |

## 8. 对我们设计文档的具体修订建议

| # | 修订项 | 建议动作 |
|---|---|---|
| 1 | **新增业务域：监管报送 / 备案** | 在 §4 增加模块，覆盖房管局备案、公租房管理信息系统对接、公安可信身份平台、住建报送、数据导出 |
| 2 | **新增业务域：多经管理** | 广告位、增值服务、商铺、公共空间经营（物业/园区/公寓场景） |
| 3 | **新增业务域：巡房 / 入户走访** | 与"智慧巡更（保安打点）"区分；支撑漳州标"替代入户走访"要求 |
| 4 | **空间树增加"床位"层级** | 片区→楼栋→单元→楼层→房间→**床位**（宿舍场景必需） |
| 5 | **审批流引擎提升为内核级独立模块** | 明确"流程设计器 + 节点 + 条件分支 + 会签 + 加签转办" |
| 6 | **部署形态由两档改三档** | 公有云 / 私有云 / 私有化，明确各档定制边界与升级责任 |
| 7 | **组织模型补"多账套"与两种组织形态** | 支持多主体多账套；支持"集团-项目-楼栋"与"集中式门店"两种形态 |
| 8 | **保障房拆为三个子策略** | 保租房 / 公租房 / 人才公寓：共用主流程，差异在准入条件、租金标准、补贴方式、退出规则 |
| 9 | **新增集成方向：企业 HR 系统** | 宿舍/园区场景：入职自动授权、离职自动回收 |
| 10 | **合同域补"一键还原"与电子签章选型** | 评估契约锁 / E签宝 |
| 11 | **账务域补"未知款项挂账关联应收"与账务数据校验** | 资金对账刚需 |
| 12 | **安全能力补"单设备登录限制"** | 与"手机唯一性绑定"呼应 |
| 13 | **公寓/出租房场景包补"线索管理 + 营销中心"** | 归入场景包，不进内核 |
| 14 | **补"失信名单/违规对象名单"** | 支撑转租转借处置 |

## 5. ⚠️ 重要：实际服务器是 MySQL 8.4.11；甲方已决策双版本兼容

甲方提供的是 **MySQL 8.4.11**（而非技术栈 D6 原写的 MySQL 8.0）。**甲方已决策：8.0 与 8.4 两者都支持，DDL 无需改动。**

| 结论 | 说明 |
|---|---|
| ✅ **该 DDL 在 8.4.11 上完全兼容** | 118 条语句零失败，含 `utf8mb4_0900_ai_ci` 排序规则、`JSON` 列、`DATETIME(3)`、分区表 |
| ✅ **8.0 侧经定向兼容性审查通过** | 见 §5.1 |
| ✅ **两版本对本项目无实质差异** | 未使用任何 8.0 已弃用构造，也未使用任何 8.4 专有构造 |

### 5.1 8.0 侧兼容性审查结论

**DDL 中确认不存在**：

| 类别 | 检查结果 |
|---|---|
| 8.4 专有构造 | **无** |
| 8.0 已弃用构造 | **无**（无 `ZEROFILL` / `VALUES()` / `SQL_CALC_FOUND_ROWS` / `utf8mb3` / `mysql_native_password`） |
| `AUTO_INCREMENT` | **无**（主键由应用层生成雪花 ID） |
| `TIMESTAMP` 列 | **无**（统一用 `DATETIME(3)`，规避时区与精度差异） |
| 生成列 / 函数索引 / 降序索引 / `CHECK` 约束 / 全文索引 / 空间类型 | **均未使用**（这些正是版本行为差异区） |

**所依赖的特性在两版本中完全一致**：

| 依赖特性 | MySQL 8.0 | MySQL 8.4 |
|---|---|---|
| `utf8mb4_0900_ai_ci` | 8.0.1+ 支持 | 支持 |
| `JSON` 数据类型 | 支持 | 支持 |
| `DATETIME(3)` 小数秒 | 支持 | 支持 |
| `RANGE` 分区 + `TO_DAYS()` | 支持 | 支持 |
| 分区表主键须含分区键 | 强制 | 同 |

> ⚠️ **仅存的诚实保留**：8.0 侧为**静态审查**结论，**未在真实 8.0 实例上执行过**。
> 若要 100% 闭环，建议在任一 8.0.x 实例复跑 P1→P5（脚本已备，预期同样 118/118 通过）。

## 7. 验证方法与可复现性

| 项 | 说明 |
|---|---|
| 连接方式 | PyMySQL 2.2.8（`pymysql.connect`），UTF-8，`sql_mode` 保持服务器默认（含 `ONLY_FULL_GROUP_BY`、`STRICT_TRANS_TABLES`） |
| 语句切分 | 自研顶层分号切分器（正确处理字符串字面量、`--` 行注释、`/* */` 块注释） |
| 库重建 | 每次验证前 `DROP DATABASE IF EXISTS bp_platform` 后重建，保证干净 |
| 数据安全 | 全部写测试均 `ROLLBACK`，**未在库中遗留任何测试数据**；未触碰任何已有库 |
| 可复现 | 脚本：`_调研/_run_ddl.py`（执行）、`_调研/_verify_db.py`（回读）、`_调研/_smoke.py`（冒烟） |

> **对目标库的影响**：仅新建了一个独立库 `bp_platform`。该服务器原本只有 `information_schema` / `mysql` / `performance_schema` / `sys` 四个系统库，**无用户数据被读取或修改**。

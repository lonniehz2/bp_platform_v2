# 智慧物业 V1 完整菜单设计

> 版本：V1.1 菜单与流程设计  
> 适用范围：物业公司租户、多项目、多业态  
> 前提：不修改保障房现有核心表；复用组织、空间、房源、人员、设备、合同、账单、押金、流水、抄表、能耗、通行、工单等能力，通过物业场景和权限做隔离。

---

## 1. 设计结论

### 1.1 总体思路

智慧物业不另建一套“组织、空间、房源、人员、设备”，而是：

```text
保障房平台核心能力
+ 物业项目/物业角色/物业收费场景
+ 菜单分组和项目上下文
```

菜单按实际物业公司的工作流组织，而不是按技术模块堆叠。

### 1.2 一级菜单

建议 10 个一级菜单：

```text
工作台
项目与资产
客户与人员
合同与租赁
收费与账务
计量与能耗
服务与监督
通行与设备
经营分析
系统与数据
```

原来的“保障与资格”在物业场景下不出现：

```text
申请受理
轮候管理
配租摇号
公示管理
年审复核
保障资格
```

人员、实名核验、合同、房源、空间、账单、押金、流水、抄表、能耗、通行、设备、工单、投诉等保留。

### 1.3 关键设计判断

| 问题 | 建议 |
|---|---|
| 物业项目是否是组织 | 是，项目是 `bp_iam_org` 的 `PROPERTY_PROJECT` 节点 |
| 物业项目层级 | 物业公司 → 区域/城市公司 → 物业项目；项目下可再设服务处 |
| 五级地址 | 中文界面项目必须填写省/市/区县/街道/社区 + 详细地址；其他语言不强制 |
| 房屋是否另建 | 不另建，复用 `bp_asset_space` + `bp_asset_house` |
| 房屋空间层级 | 项目 → 楼栋/商业街/车库 → 单元 → 楼层 → 房间/商铺/办公 |
| 设备绑定在哪里 | 绑定在空间节点，不绑定在房屋；子空间自动继承 |
| 人员类型 | 人员主档 + 项目/房屋关系类型，不在人员主档写死单一类型 |
| 物业费是否有合同 | 不建议每户生成一份真实合同；用“计费方案/默认计费合同”自动出账 |
| 商铺/车位/场地合同 | 保留统一合同台账、变更、换房/调铺、退租 |
| 优惠是否用补贴 | 可以复用补贴/减免引擎，但物业优惠与政府补贴要分类型、分报表、分审批 |
| 押金退款 | 保留押金与退款，扩展租赁押金、装修押金、钥匙押金等业务类型 |

#### 项目组织层级

```text
租户
└─ 物业公司（COMPANY）
   ├─ 区域/城市公司（COMPANY 或 DEPARTMENT）
   │  └─ 物业项目（PROPERTY_PROJECT）
   │     └─ 服务处/管理处（DEPARTMENT，可选）
   └─ 物业项目（PROPERTY_PROJECT）
```

#### 五级地址规则

中文界面：

```text
省 province
市 city
区县 district
街道 street
社区 community
详细地址 address
```

规则：

- `PROPERTY_PROJECT` 节点在中文界面必须填写五级地址。
- 详细地址必填。
- 其他语言界面不强制五级地址，但已有数据照常显示。
- 合同、账单、收据、发票中的项目地址统一取项目组织的标准地址。
- 行政区划继续使用现有 `/sys/regions/children` 级联。

#### 人员类型

人员类型不写在人员主档上，而是通过项目/房屋关系表达：

```text
OWNER        业主
FAMILY       家人
TENANT       承租人
COHABITANT   同住人
VISITOR      访客
SERVICE      服务人员
STAFF        物业工作人员
```

原因：

- 同一人可能在一套房是业主，在另一套房是承租人。
- 同一人可能是某商铺承租人，同时是住宅业主。
- 访客是短期关系，不应污染人员主档。
- 物业工作人员通过用户账号 + 物业角色表达，不进入业主关系表。

```text
SHOP_LEASE       商铺租赁
PARKING_LEASE    车位租赁
SITE_LEASE       场地租赁
AD_LEASE         广告位租赁
OFFICE_LEASE     办公租赁
PROPERTY_SERVICE 物业服务/默认计费合同（系统合同，可选）
```

#### 合同状态

```text
DRAFT → PENDING_APPROVAL → ACTIVE → CHANGING → TERMINATED / EXPIRED
```

#### 合同与默认计费合同

不建议把每户物业费都做成真实合同：

- 真实合同用于商铺、车位、场地、广告位等有签署文件的业务。
- 物业费、能耗费、车位管理费使用“计费方案”自动出账。
- 如果审计要求必须有合同，可生成 `PROPERTY_SERVICE` 系统合同：
  - `system_flag=1`
  - 不进入租赁合同台账默认列表
  - 自动续签
  - 只作为账单来源和审计依据

对应关系：

```text
真实租赁合同 → 租金/押金/退租
计费方案     → 物业费/能耗费/车位管理费
临时停车     → 临停记录和临停账单
```

#### 优惠与补贴的建议

用户提出“优惠金额是否可以用补贴管理机制实现”。建议：

- 可以复用“补贴/减免”引擎的审批、生效期、抵扣记录能力。
- 但物业优惠 ≠ 政府补贴，必须分开：
  - `biz_type=PROPERTY_DISCOUNT`：物业优惠、开业优惠、长租优惠、老业主优惠。
  - `biz_type=GOV_SUBSIDY`：政府补贴、保障补贴。
- 账单上保留：
  - 原应收
  - 优惠金额
  - 补贴金额
  - 实收
  - 优惠/补贴原因
- 权限上：
  - 客服可发起优惠申请；
  - 财务/项目经理审批；
  - 收费员只能使用已审批优惠，不能改政策。
- 报表上：
  - 物业优惠单独统计，不能冲减政府补贴口径。

推荐数据：

```text
prop_discount_policy
prop_bill_discount
prop_subsidy_grant（可复用现有补贴表，增加 biz_type）
```

设备绑定原则：

```text
设备 → 空间节点
楼栋设备 → 楼栋及所有下级继承
单元设备 → 单元及所有下级继承
房间设备 → 当前房间
不绑定到房屋台账，避免房源变更导致设备丢失
```

## 4. 关键业务流程

### 4.1 项目初始化

```text
创建物业公司组织
→ 创建区域/城市公司
→ 创建物业项目（PROPERTY_PROJECT，五级地址）
→ 创建空间层级（楼栋/单元/楼层/房间/商铺）
→ 导入房屋台账
→ 创建车位台账
→ 导入/创建人员
→ 建立业主/承租人关系
→ 配置收费项目
→ 配置计费方案
→ 设备绑定
→ 开始出账
```

### 4.2 业主/住户入住

```text
人员档案
→ 实名核验
→ 选择房屋
→ 建立关系（业主/家人/承租人/同住人）
→ 主业主确认
→ 绑定门禁/车位
→ 生成首期账单
```

### 4.3 租赁合同

```text
选择租赁标的（商铺/车位/场地/广告位）
→ 填写承租方、租期、租金、押金
→ 提交审批
→ 合同生效
→ 收取押金
→ 按周期生成租金账单
→ 合同变更/调铺/退租
→ 退租结算与押金退款
→ 设备/通行解绑
```

### 4.4 物业费自动出账

```text
计费方案（项目/楼栋/房屋）
→ 批量生成账单
→ 优惠/补贴计算
→ 账单发布
→ 收款
→ 生成 PDF 收据
→ 开电子发票
→ 欠费进入催缴
```

### 4.5 水电与公摊

```text
表计档案
→ 抄表
→ 用量计算
→ 水电账单
→ 公摊总额录入
→ 按面积分摊
→ 生成公摊账单
→ 收款
```

### 4.6 欠费催缴

```text
欠费清单
→ 选择账单
→ 短信/微信/邮件
→ 生成催缴任务
→ 记录发送结果
→ 跟踪回款
```

### 4.7 服务工单

```text
业主/客服报修
→ 工单受理
→ 派单
→ 处理
→ 回访
→ 评价
→ 归档
```

### 4.8 设备与通行

```text
设备入库
→ 绑定空间
→ 授权人员
→ 通行
→ 记录
→ 告警处理
```

## 5. 角色与菜单权限矩阵

角色建议：

```text
PROPERTY_MANAGER    物业项目经理/管理员
PROPERTY_STEWARD    客服/管家
PROPERTY_CASHIER    收费员
PROPERTY_FINANCE    财务
PROPERTY_ENGINEER   工程/设备
PROPERTY_AUDITOR    只读/审计
```

图例：

```text
● 可查看和办理
◐ 只读/有限办理
○ 不可见
```

| 菜单组 | 项目经理 | 客服/管家 | 收费员 | 财务 | 工程/设备 | 只读/审计 |
|---|---|---|---|---|---|---|
| 工作台 | ● | ● | ● | ● | ● | ● |
| 项目与资产 | ● | ◐ | ◐ | ◐ | ◐ | ◐ |
| 客户与人员 | ● | ● | ◐ | ◐ | ○ | ◐ |
| 合同与租赁 | ● | ● | ◐ | ◐ | ○ | ◐ |
| 收费与账务 | ● | ◐ | ● | ● | ○ | ◐ |
| 计量与能耗 | ● | ◐ | ◐ | ◐ | ● | ◐ |
| 服务与监督 | ● | ● | ○ | ○ | ◐ | ◐ |
| 通行与设备 | ● | ◐ | ○ | ○ | ● | ◐ |
| 经营分析 | ● | ◐ | ◐ | ● | ◐ | ● |
| 系统与数据 | ● | ○ | ○ | ◐ | ○ | ◐ |

关键限制：

- 收费员不能修改收费项目和计费方案。
- 客服/管家可以发起优惠申请，但不能审批。
- 财务负责收费配置、优惠审批、退款审批、发票开具。
- 工程只能管设备、表计、抄表、能耗、告警。
- 项目经理拥有项目内全部业务权限，但不能跨项目。
- 只读角色不能写业务数据。

## 9. 最终建议

1. **菜单按业务分组，不按表分组**  
   项目、房屋、人员、合同、账单、设备分别对应实际岗位的工作入口。

2. **保障房菜单不删能力，只做场景隐藏**  
   人员、合同、房源、空间、账单、押金、流水、抄表、能耗、通行、工单继续复用。

3. **物业费不强行合同化**  
   用“计费方案”自动出账；需要审计时再生成系统合同，避免每户一份合同造成数据膨胀。

4. **优惠与政府补贴分账**  
   可以复用补贴引擎，但必须区分 `PROPERTY_DISCOUNT` 与 `GOV_SUBSIDY`，审批和报表分开。

5. **设备绑定空间，不绑定房屋**  
   与保障房一致，避免房源变更、拆合房导致设备丢失。

6. **五级地址只在中文界面强制**  
   符合国内项目备案要求，同时不阻塞其他语言场景。

7. **先做 P0 菜单和流程，再做分析报表**  
   P0：项目、空间、房屋、人员、合同、计费方案、账单、收款、收据、设备绑定。  
   P1：优惠、押金退款、发票、催缴、抄表、公摊、工单、通行。  
   P2：经营分析、服务评价、报表订阅。

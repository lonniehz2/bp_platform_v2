# 智慧物业 V1 设备业务平台能力建议

> 范围：只讨论业务系统中的设备功能，不涉及 IOT 平台的设备协议、通信、控制和实时运行  
> 结论：设备业务台账、空间绑定、责任归属、运维履历可以升级为平台能力；IOT 运行能力仍归 IOT 平台

---

## 1. 先分清两类设备能力

### IOT 平台负责

```text
设备接入
协议/SDK
设备身份
在线心跳
电量、信号、固件
远程开门/远程控制
设备告警
门禁/车闸/梯控实时控制
卡片/人脸/指纹下发
设备通信日志
设备厂商协议
```

### 业务平台负责

```text
设备资产台账
设备编号/资产编号
设备类型/型号/厂商
设备所属项目/空间
设备安装位置
安装时间/验收
设备责任人/管理人/维保人
设备状态：在用/维修/停用/报废
质保期
采购/供应商/合同
设备绑定/解绑/转移
设备运维/维修履历
设备二维码/标签
设备业务统计
```

业务平台不直接控制设备，只维护设备作为“资产”的业务属性。

---

## 2. 设备业务能力是否适合平台化

适合，原因：

```text
保障房：门锁、水电表、门禁
物业：门锁、电梯、水泵、消防、水电表
园区：门禁、车闸、监控、水电表
校园：门禁、水电表、广播
公寓/酒店：门锁、水电表、门禁
```

这些场景都需要：

```text
设备台账
绑定空间
责任人
安装/验收
维修/更换
报废
统计
```

差异只在设备类型和业务规则，不在设备资产管理框架。

所以建议升级为**平台资产能力**，而不是物业专属。

---

## 3. 建议的平台能力

### 3.1 平台设备资产台账

建议复用并扩展：

```text
bp_dev_device
```

不建议新建：

```text
prop_device
prop_device_asset
```

设备台账应作为平台资产主数据，场景只做筛选和扩展。

建议字段分层：

```text
业务资产字段（平台可维护）
  asset_no
  device_name
  device_type
  device_model
  vendor
  org_id
  space_id
  install_address
  install_time
  install_status
  owner_person_id
  admin_person_id
  maintain_org_id
  warranty_start
  warranty_end
  purchase_date
  supplier_id
  contract_id
  asset_status
  business_status
  qr_code
  source_system

IOT 运行字段（IOT 同步，业务只读）
  iot_device_id
  device_mac
  online_status
  online_time
  offline_time
  battery
  rssi
  soft_version
  hard_version
  last_report_time
  status_sync_time
```

关键原则：

```text
IOT 是设备身份、在线状态、运行状态的源
业务平台是设备资产属性、空间归属、责任归属、运维履历的源
两边通过 iot_device_id 关联
业务平台不直接写在线状态、电量、信号
```

### 3.2 设备空间绑定

设备绑定在空间，不绑定房屋：

```text
项目
→ 楼栋
→ 单元
→ 楼层
→ 房间/商铺
```

绑定规则：

```text
楼栋设备：楼栋及下级继承
单元设备：单元及下级继承
楼层设备：楼层及下级继承
房间设备：当前房间
```

业务平台维护：

```text
设备与空间绑定关系
绑定时间
绑定人
解绑时间
解绑原因
转移记录
```

建议：

```text
bp_dev_bind_log
```

### 3.3 设备业务状态

不要把 IOT 在线状态和业务状态混在一起。

业务状态：

```text
IN_STOCK       在库
INSTALLING     安装中
ACTIVE         在用
REPAIRING      维修中
DISABLED       停用
SCRAPPED       报废
```

IOT 状态：

```text
ONLINE / OFFLINE / FAULT
```

业务页面显示：

```text
业务状态 + IOT 在线状态
```

但不能用 IOT 在线状态替代业务状态。

### 3.4 设备责任归属

平台能力应支持：

```text
所属组织
所属项目
所属空间
所有权人
管理人
维保人
维保供应商
```

对应字段：

```text
org_id
owner_person_id
admin_person_id
maintain_org_id
supplier_id
```

### 3.5 设备运维履历

设备维修、更换、保养、巡检记录，建议关联平台工单：

```text
设备
→ 工单
→ 维修记录
→ 更换记录
→ 费用
```

业务平台保留：

```text
bp_dev_service_record
  device_id
  workorder_id
  service_type
  service_time
  service_user
  cost
  result
  remark
```

IOT 平台只提供设备运行/告警事件，不管理维修费用和供应商。

### 3.6 设备组

建议区分：

```text
IOT 设备组：用于通信、控制、批量下发
业务设备组：用于资产统计、巡检、维保、责任划分
```

不要混用同一个组。

业务设备组：

```text
bp_dev_group
  group_code
  group_name
  group_type = BUSINESS
  org_id
  project_id
  status
```

如果 IOT 也有设备组，通过 `source_system` 或独立表隔离。

### 3.7 设备类型字典

建议平台级：

```text
bp_device_type
  type_code
  type_name
  scene_code
  category
  status
```

场景示例：

```text
PROPERTY：门锁、电梯、水泵、消防、水电表
GUARANTEE：门锁、水电表、门禁
PARK：道闸、监控、门禁
CAMPUS：门禁、广播、水电表
```

物业只引用，不重复建一套设备类型。

### 3.8 设备二维码/资产标签

平台能力：

```text
生成设备二维码
扫码查看设备详情
扫码报修
扫码巡检
```

二维码内容只放设备资产 ID，不放敏感信息。

---

## 4. 不建议放进业务平台的能力

```text
设备通信协议
设备 SDK
设备固件升级
远程开门/远程控制
设备实时心跳
设备告警规则
门禁/车闸/梯控实时控制
卡片/人脸/指纹下发
设备厂商对接
IOT 设备组控制
```

这些属于 IOT 平台。

业务平台可以显示 IOT 同步过来的状态，但不直接控制设备。

---

## 5. 平台分层建议

```text
平台资产层
├─ bp_asset_space_template
├─ bp_asset_type
├─ bp_asset_space
├─ bp_asset_house
├─ bp_dev_device          设备资产主数据
├─ bp_dev_group           业务设备组
├─ bp_dev_bind_log        空间绑定履历
├─ bp_device_type         设备类型字典
└─ bp_dev_service_record  设备运维履历

IOT 平台
├─ 设备接入
├─ 设备运行状态
├─ 设备控制
├─ 设备告警
├─ 门禁/车闸/梯控
└─ 卡片/人脸/指纹

场景层
├─ prop_*    物业设备筛选、物业工单、物业报表
├─ guarantee_* 保障房设备筛选
└─ park/campus_* 场景设备筛选
```

## 6. 与现有 `bp_dev_device` 的关系

现有表已经包含一部分设备台账字段：

```text
device_id
device_mac
device_name
device_type
device_model
org_id
space_id
install_address
install_time
install_user_id
online_status
battery
rssi
owner_person_id
admin_person_id
maintain_org_id
install_status
device_status
```

建议：

```text
保留 bp_dev_device 作为平台设备资产主表
补充业务字段：asset_no、vendor、warranty、purchase_date、supplier_id、contract_id、asset_status、qr_code
IOT 字段标记为同步只读
不新建 prop_device
```

如果担心影响现有保障房设备功能，可以：

```text
新增字段全部 nullable
IOT 同步字段不改变原逻辑
业务状态新增字段，不复用 online_status
```

## 10. 结论

业务平台中的设备内容可以升级为平台能力，但只包括：

```text
设备资产台账
设备空间绑定
设备责任归属
设备业务状态
设备运维履历
设备组/类型
设备二维码
```

不包括：

```text
设备通信、控制、告警、门禁、卡片、实时状态
```

建议复用 `bp_dev_device`，补充业务字段，不新建 `prop_device`：

```text
平台负责设备作为资产
IOT 负责设备作为联网设备
两边通过 iot_device_id 关联
```

这样物业、保障房、园区、校园都能共用设备资产能力，同时不会把 IOT 平台能力重复建到业务平台里。

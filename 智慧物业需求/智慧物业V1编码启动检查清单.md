## 3. 编码前需要确认的开放问题

| 编号 | 问题 | 建议 |
|---|---|---|
| Q1 | 停车过渡菜单放在哪里 | 放在“项目与资产 → 车位管理（过渡）” |
| Q2 | 默认物业服务合同按户还是按项目/楼栋生成 | 先按户生成系统合同，后续支持批量 |
| Q3 | 审核中心审批层级 | 客服发起，财务/经理终审，金额分级 |
| Q4 | 资产类型是租户级还是项目级字典 | 租户级字典，项目引用；项目可覆盖单价 |
| Q5 | 公共能耗分摊是否本期做资产类型系数 | 本期先按面积，系数后续扩展 |
| Q6 | 人脸照片存储周期和删除策略 | 人员注销后按策略清理，不进入普通导出 |
| Q7 | 供应商管理是否 P0 | 建议 P1，不阻塞收费主链路 |
| Q8 | 现有停车菜单是否继续可操作 | 保留入口，不扩展新功能 |

## 4. 建议的编码启动顺序

```text
第 0 步：数据模型/DDL/接口/权限评审
第 1 步：菜单壳改造，11 组菜单
第 2 步：基础配置
        空间结构模板、资产类型、人员类型
第 3 步：项目与资产
        五级地址、空间层级、房屋台账
第 4 步：客户与人员
        业主与住户、人员档案、人员组、业主审核
第 5 步：收费
        收费项目、计费方案、合同选择方案
        账单、收款、收据
第 6 步：审核中心
第 7 步：测试与迁移
```

第一段编码只做一条垂直链路：

```text
项目
→ 空间模板
→ 房屋/资产类型
→ 业主
→ 合同选择方案
→ 账单
→ 收款
→ 收据
```

## 6. Go / No-Go 标准

可以开始编码的条件：

```text
数据模型评审通过
接口和权限清单评审通过
P0 页面交互确认
迁移和回滚方案确认
验收用例确认
```

不满足以上条件时，不建议直接写业务代码，否则后面容易反复改表、改接口、改权限。

---

## 7. 结论

开始编码前，还需要：

```text
1. 冻结数据模型和 DDL
2. 冻结接口、路由和权限
3. 确认 P0 页面交互
4. 确认现有数据迁移方案
5. 确认验收用例和回归范围
```

这 5 项完成后，再按“菜单壳 → 基础配置 → 项目/空间 → 人员/审核 → 计费/账单/收款”的顺序编码。

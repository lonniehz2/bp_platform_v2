## R1 说明

### 字段

```text
bp_person.face_photo_url   可空
或
prop_person_ext.face_photo_url
```

### 规则

```text
非必填，不阻塞人员建档
只存文件服务 URL，不存 base64
支持 JPG/PNG，建议不超过 2MB
支持上传、预览、替换、移除
仅在人员详情、审核详情展示
列表不展示照片缩略图
本期只做照片存档，不做人脸识别、不做门禁下发
后续对接 IOT 时再定义人脸下发、同步、删除规则
```

### 接口

```text
POST /files/upload
POST /persons
PUT  /persons/{id}
GET  /persons/{id}
```

### 权限

```text
查看：property:person:view
上传/替换/移除：property:person:edit
审核查看：property:review:view
```

### 涉及页面

```text
客户与人员 → 人员档案
审核中心 → 业主审核
审核中心 → 实名审核
```


## R2 说明

收费项目类别固定为：

```text
物业费
能耗费
水费
电费
车位管理费
租金
其他
```

规则：

```text
收费项目先归入以上类别，再配置具体收费项目
其他类别下可细分多经收入、其他收入
车位管理费是收费类别，不恢复停车运营菜单
计费方案选择收费项目时只能从以上类别中选
```


## R3 说明

已确认：

```text
1. 11 组菜单最终确认
2. 空间结构模板按项目选择
3. 审核中心独立一级菜单
4. 计费方案不替代合同，合同中选择计费方案
5. 停车/IOT 菜单先不隐藏，后续扩充优化
```

设计处理：

```text
停车管理作为过渡菜单保留在项目与资产下
不删除现有停车代码和数据
本期不扩展车闸/停车订单/停车券
IOT 不新增本期菜单，后续独立扩充
合同可关联一个或多个计费方案
账单记录 contract_id、scheme_id
空间模板按项目独立选择，最多 6 级
```

## R5 说明

已确认：

```text

物业服务合同按项目和业委会/资产方签订整体合同
```

## R6 说明

空间结构模板从物业专属表调整为平台资产基础配置：

```text
bp_asset_space_template
  tenant_id
  scene_code        PROPERTY / GUARANTEE / PARK / CAMPUS ...
  template_code
  template_name
  level_count
  levels_json
  version_no
  status
```

资产类型也调整为平台级：

```text
bp_asset_type
  tenant_id
  scene_code
  type_code
  type_name
  type_category
```

项目组织增加：

```text
bp_iam_org.space_template_id
bp_iam_org.default_asset_type_code
```

原则：

```text
模板和资产类型是平台资产基础能力
物业、保障房、园区、校园共用
不同场景用 scene_code 隔离
项目只选择模板，不重复建一套空间结构
物业专属信息仍放 prop_unit_ext 等物业表
```
